# 视觉识别

场景可由地区声纹或固定频率截图 OCR 独立确认，统一协调结果；TZ 通过截图文字 OCR 确认，不依赖紫色。掉落只由声纹确认，不进行图像核验。确认 #24–#33 符文后按事件保存截图，不启动掉落 OCR，也不影响掉落记账。场景与聊天配置通过
`ModuleConfigStore` 保存在 `%APPDATA%/D2RHub/modules/visual-recognition/config.json`。

## 使用

- 设置 → 自动跟房 → 房间与操作 → 拼房模式，或主页“跟房配置”快捷面板：默认使用原版创建／跟房且不发送、识别聊天信号；拼房主机只在创建前发送；拼房跟随只监听本机主号聊天并让主号及小号一起加入；超级迪亚波罗使用创建快捷键，让主号、小号按配置顺序各自创建序号递增、密码相同的独立房间，不执行跟随或聊天监听。四种模式互斥，共用同一份房间规则、账号和快捷键配置。
- 拼房跟随中，原创建快捷键也执行加入，不在本机建房。主号自动纳入加入队伍，不需要重复选为小号。切换模式会取消旧流程并更新信号会话；旧待触发信号不能越过模式切换执行。默认模式为旧配置迁移后的起点，旧视觉发送／监听开关不再决定运行行为。
- 设置页修改自动保存；快捷面板关闭、点击外部、按 Esc 或离开页面时自动保存模式和房间规则；无效输入或保存失败会提示，正常关闭时保留草稿供修正。规则复制／粘贴只同步房名和密码，不覆盖本机协作模式或账号。仅跟房共用窗口消息及共享 Ctrl 输入，无前台激活要求。
- 当前发送格式为 `*********** 077 ***********`（数字至少三位），主机创建前以相同轮次连发三条，打开聊天框后及每条提交后各等待 50ms，按键和粘贴仍遵循配置时序。按配置间隔检查聊天截图，从下往上宽松检测两侧连续小符号包围较高数字的布局，只裁切中间数字送入 OCR；确认比去重记录更新的后缀后立即停止向上扫描。首次检查仅建立旧消息基线。后缀只用于去重，不比较或修改本机房号。新轮次触发后仅等待配置的跟房延迟，始终使用本机规则。两端须更新并自行复制／粘贴规则同步。
- 手动修改房名前缀、密码、起始序号或数字位数并成功保存后，会开启新的聊天去重会话；粘贴规则后成功保存也会重置，即使粘贴内容相同。快捷编辑离开时自动保存，设置页沿用自动保存。保存失败不会重置；普通开关监听、重启 Hub、系统自动递增房号不会重置。
- 重置同时取消旧的待跟房任务并清空 OCR 缓存；第一帧有效画面仍仅建立基线，不触发旧消息。如果重新从小序号开始，应先让旧的大序号消息离开识别区域，避免它再次成为基线。
- 已消费序号不会因消息消失或加载而重新触发。首次画面作为基线忽略；旧版、截断和格式不完整的信号忽略。详情见下方聊天 OCR 节奏。
- 设置 → 识别与统计 → 记录内容 → 场景计时与掉落截图：地区 OCR 设置保留，并提供打开掉落截图目录的入口。
- ROI 使用游戏客户区比例；提供一次性截图预览。最小化、黑帧、无法捕获均为“无法核验”。WGC 在系统支持的情况下可能显示捕获边框。
- 高号符文截图保存到应用数据目录的 `stateData/drop-screenshots/YYYY-MM-DD/`。文件名含毫秒时间、时区、场景、符文和观测 ID。数据库 `drop_observations.screenshot_path` 只保存相对于 `stateData` 的路径；图片不写入 SQLite。保存失败不影响声纹记录。

## 资源分发

安装包只包含 `resources/vision-resources-v1.json` 的小型版本清单，不包含 ONNX 模型、字典或 ONNX Runtime DLL；禁用 `ort` 的下载／复制 DLL 默认构建特性。模型内含字符字典元数据，无独立字典下载。

需要 OCR 的功能及其所属模块启动时检查线上清单、版本和 SHA-256；线上清单不可用、来源校验失败或接口不兼容时采用兼容缓存或随软件携带的固定版本清单。可在设置中“诊断与资源 → 重试资源准备”重新检查。仅发送聊天信号不需要 OCR；监听聊天信号现在需要按需下载并加载 OCR，以读取明文轮次后缀。

资源缓存为 `%APPDATA%/D2RHub/resources/vision/`，按内容摘要命名。下载有大小上限、SHA-256 校验、三次有限重试、临时文件、取消清理和原子切换；更新完成前保留旧资源。客户端遵循系统代理。文件损坏时重新下载或由已校验 ZIP 修复 DLL。清单只允许指定上游／项目发布仓库的 HTTPS 地址。

## 实现与限制

注册 `visual-recognition` capability，共享一个有界 worker 与 OCR session；CPU 推理限制 2 个内部线程。使用 Windows Graphics Capture 按需取帧，Rust 完成颜色特征、背景矩形和投影裁切；聊天保留原有行分割，不引入 OpenCV、Python 或通用文本检测模型。地区只 OCR 原始 RGB 裁片，不做二值化重试，也不对文字做连通域拆字或形态学操作。截图不上传；场景及聊天图片不常态落盘，高号符文留念图按事件保存。

聊天先检查同一行两侧连续小符号包围较高数字的布局，再裁切中间数字送入 OCR；每侧至少 4 个可见符号，不要求精确星号数量或笔画。地区启用后每秒检查配置 ROI 的红字形态，不依赖 TZ 或未知 Area 声纹触发截图；要求红字有文字行的高度、宽高比、密度及多处笔画分隔，再对原图裁片做 OCR。OCR 至少 0.90 分、有“进入／進入／Entering”前缀、去掉前缀后匹配统一后的场景名称才采纳。名称驱动分段：进入野外／地下城开始计时，同一区域不同楼层合并为一个统计场景，换层不中断计时，换到其他区域结算上一分段，回城结束计时。识别层保留完整楼层名，在计时入口去掉中文数字楼层后缀或英文 Level 数字后缀；不改写历史数据库。同一段连续播报不会重复重置；文字消失后再次进入同名地区可以开始新分段。计时采用实际经过时间，不再依赖音频帧数。地区名称沿用 Mod 地区目录，进入识别层前转成不含 Area ID 的名称与城镇／野外属性；同名目录项合并并保留各自的已知简繁体及英文译名。七座“塔·拉夏之墓”合并统计，第二幕与第三幕的同名“下水道一层”也合并；不同楼层归入对应区域，“塔·拉夏的墓室”仍与“塔·拉夏之墓”分开统计。Area ID 不再作为匹配或切段条件，兼容字段 `current_area_id` 对 OCR 场景返回 `null`。只有内置目录时覆盖范围有限；已有历史记录不改写。

地区提示下方的有效文字行送入 OCR；无地区红字时检查配置区域下半部分。识别结果包含「邪恶区域恐怖地带」任意一个字，或英文 `Terrorized` / `Terror Zone`，即标为 TZ，不依赖文字颜色。TZ 提示稍晚出现只补充当前分段的元数据，不重置起点或掉落；提示淡出不撤销该分段的 TZ 状态。过期结果不能覆盖较新的场景。

主界面 OCR 按用户要求暂缓。直接退出到选人／大厅不会自动结束当前计时；下一次识别到场景或监控结束时才结算，可能包含菜单停留时间。地区 OCR 关闭时仍可由有效的地区声纹确认场景；成品关闭场景声纹且地区 OCR 也关闭时，没有自动切换及计时依据。

当前工作区加工器整体配方 r26、音频功能组 r5，生成地区环境声纹、掉落／敌对声纹及完整 OCR 地区目录，不生成 TZ、主界面声音。已安装的 r4 成品可能没有地区声纹，仍可独立使用 OCR。旧成品需从原始未加工来源重做；不能把含旧场景音的成品作为干净基线继续加工。OCR 模型及运行库仍按需下载。

声纹经音频确认及去重后直接入库；#24–#33 异步请求一次完整客户区截图。旧低分核验、强制确认与标签可见配置字段不再生效。

场景及聊天 OCR 仍依赖文字可见性和可捕获的窗口；高号符文截图只作留念，不读取名称、不修正掉落身份。最小化、黑帧或保存失败只写日志，不回滚掉落。

## 验证

### 场景双渠道与楼层统计

地区截图保持每秒检查一次的原流程：固定 ROI、红字形态检测、原图 OCR、0.90 分及进入前缀和精确别名匹配；保留缓存及失败重试，不增加模糊匹配或动态截图频率。声纹不再暂停、替换或取消 OCR 任务；未知 Area、占位名称不切段，也不取消等待中的截图结果。

两路映射成功后进入统一结果协调层，任一路都可独立确认场景。新的有效入场 OCR 可立即确认；重复缓存结果不能覆盖更新的场景。与已确认视觉场景冲突的声纹，需要至少两次同区域观测、间隔至少 500ms 且在 6 秒确认窗口内，并距该视觉确认至少 2 秒，才允许切换；相同区域的重复声纹不重置计时。早于较新确认结果提交的 OCR 结果被丢弃，TZ 晚出现只补充当前区域。

同一区域的一／二／三层等共用一个统计名称、起点和掉落分段。离开到其他区域再返回仍开始新段；同一具体地点的新入场播报仍可区分再次进入。同名墓室合并规则不变，独立命名的墓室和古墓不按近似文字混为一处。

### 视觉诊断日志

在自动跟房的聊天信号设置或识别与统计的视觉设置中启用“诊断与资源 → 记录诊断日志”，开关自动保存并生效，成功后显示“已保存”。数值及截图范围在输入完成、离开输入框时自动保存；保存失败会明确提示，可点击“保存修改”重试，折叠重开保留当前草稿。默认关闭，旧配置自动兼容。可点击同区域的“打开日志目录”。

诊断内容写入现有 `%APPDATA%/D2RHub/logs/` 下本次运行的 `.log`，以 `[VisionDiagnostic]` 标记，后续内容为单行 JSON。日志沿用应用原有文件保留策略，不保存截图。

- `worker_start`／`worker_ready`／`worker_stop`：功能组合、ROI、轮询间隔、OCR 是否加载及资源准备耗时；失败输出 `resource_or_model_error`。
- `trace`：任务编号、类型 `chat/area`、PID、总耗时、排队耗时及分阶段毫秒数。阶段包括截图、裁切、分割、二值化、OCR 或信号检测；次数和候选行数另记。总耗时从 worker 开始处理时计算，排队时间单独记录。
- 聊天日志记录 `ocr.decoded_tokens`（读到的轮次）、`dedup_token`（本次接受的轮次）、`dedup_watermark`（已消费最高轮次）、`local_sequence`（本机序号）、`baseline` 和 `trigger`；`dedup_persist` 是去重状态读写耗时。`chat_follow_dispatch` 只表示跟房入口是否接受，不代表服务器入房成功。
- 地区未采纳时记录名称匹配失败原因、OCR 分数及错误；高号符文截图成功或失败由 `DropScreenshot` 日志记录。
- 总计最多每分钟 120 条，达到上限后限流，下一次允许写入时用 `suppressed` 报告省略条数。诊断模式会增加少量计时和日志 I/O 开销，关闭后不输出视觉诊断记录；开启／关闭动作会记录一次状态切换。

常规 `cargo test --locked` 和前端测试不联网。显式原生 smoke test 会下载可选资源，验证校验、DLL 加载、模型字典、CTC 解码、单行文字识别：

```powershell
$env:D2RHUB_VISION_SMOKE_IMAGE = 'C:\path\signal.png' # 含 ++++ run-037 ++++ 的横向测试图片
cargo test --manifest-path src-tauri/Cargo.toml downloaded_model_smoke -- --ignored --nocapture
```

测试图只能验证该样本，不代表真实 D2R 识别精度或时延。

聊天信号可单独验证符号串检测、数字裁切、实际模型推理和解析的完整路径：

```powershell
$env:D2RHUB_CHAT_OCR_SAMPLE = 'C:\path\chat.png' # 完整同一行 *********** 014 ***********
$env:D2RHUB_CHAT_OCR_EXPECT = '14'
cargo test --manifest-path src-tauri/Cargo.toml native_compact_signal_smoke -- --ignored --nocapture
```

- 聊天日志 `line_analysis` 包含 `glyph_runs`、`marker_runs`、`geometry_windows`、`number_bounds` 和 `reason`。当前原因包括 `too_few_marker_trains`（没有两侧符号串）与 `no_numeric_center`（没有符号包围的较高数字区域）。只检查相对尺寸、同行位置与间距，不匹配星号笔画或精确数量；每侧至少 4 个可见符号，720p 的 2×2 星号也会保留在候选行中。

新配置的默认截图范围（左、上、宽、高）：地区 40%、20%、20%、9%；聊天 0%、40%、31%、40%。旧地区默认高度 4% 自动迁移为 9%，其他自定义范围保留。聊天接收与预览自动使用当前主号，旧的独立监听账号字段不再决定目标；目标或进程变化时清除待触发信号并重新建立基线。诊断日志默认关闭；仅改变诊断开关不重建 OCR 服务。

## 按需复用截图会话

截图使用 WGC 会话池，最多保留两个目标，15 秒无请求自动释放；窗口退出、最小化、尺寸或进程身份变化会淘汰旧会话，视觉服务停止时也会请求清理。支持最小更新间隔的系统会请求 100ms 的 OS 送帧下限；不支持时沿用系统行为。送帧不等于识别：无截图请求时不做 GPU→CPU 回读、RGB 转换或 OCR。

聊天和地区识别在 GPU 上裁切客户区后，只回读指定范围。CPU 直接按显存行跨度转换 RGB，省去整帧 RGBA 去填充复制和整帧 RGB 裁切。高号符文留念截图按事件请求完整客户区。客户区采用物理像素定位，不使用旧实现的标题栏高度猜测。每个请求只接受 QPC 帧时间不早于请求的画面，不保留旧图片作为超时回退。窗口边界变化或新帧超时会丢弃该次结果并淘汰会话。

诊断 trace 的 `capture_metrics` 区分 `reused`、排队 `queue_ms`、会话建立 `setup_ms`、等新帧 `wait_frame_ms`、GPU 回读 `readback_ms`、颜色转换 `convert_ms` 和总耗时 `total_ms`，并记录帧年龄及输入输出尺寸。`minimum_update_interval_ms=null` 表示系统未应用送帧间隔限制。没有实测前不承诺具体加速倍数；原 180～220ms 是旧实现全流程的测量。

可显式运行只读 A/B 基准，目标必须是非最小化的运行中 D2R 窗口，不会发送游戏按键或保存截图：

```powershell
$env:D2RHUB_CAPTURE_BENCH_PID = '实际游戏PID'
cargo test --manifest-path src-tauri/Cargo.toml compare_legacy_and_reused_gpu_roi_capture -- --ignored --nocapture
```

测试分别测量旧版完整截图＋CPU 裁切、新版首次截图和间隔 3 秒的会话复用，并确认闲置期间没有 CPU 回读。常规自动测试不访问真实游戏窗口。
