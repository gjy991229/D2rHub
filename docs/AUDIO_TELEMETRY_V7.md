# D2R 音频遥测 v7

## 目标与边界

当前 v7 方案验证三类事实：所选物品是否执行了世界掉落动画、D2R 当前处于哪个 Area，以及玩家是否已经返回主界面。地图可选女伯爵路线八个 Area 或本机游戏数据中的全部 137 个 Area。它不读取或写入游戏内存，不注入 DLL，不进行画面识别，也不依赖文件读取次数。

怪物爆出与玩家从背包丢下都会执行世界掉落动画，二者无法仅靠这一音频触发区分；因此在野外两者都会记录。背包和仓库内部移动不应记录。完全同时落地的两个同代码物品在单一混音信号里不可分辨，只能记作一次。

接收端允许配置最低记录符文编号（包含边界，例如 20 表示记录 #20–#33）。有效但低于门槛的符文只保留在诊断数据中，不写入掉落数据库或悬浮窗。所有符文和扩展物品还必须在接收端已确认当前地点为野外/地下城时才能入库；主城、主界面和尚未确认地点时的掉落声纹统一忽略。

## 已排除的错误路径

- ETW 文件请求：实机确认资源只在首次使用时读取，后续播放来自缓存，因此文件 I/O 不能代表每次事件。
- HD 实体级 `AudioEmitterComponent`：实机确认背包/仓库渲染也会创建同一实体，造成移动物品时误报；同时怪物爆落没有可靠触发，因此 v4.2 起已移除全部这类发射器。
- `SoundEnviron` 随机 Event：虽然表定义存在，但实机没有进入该播放路径，因此不再用于地点心跳。

## v7 触发与加工设计

设计依据是 [D2R Data Guide](https://locbones.github.io/D2R_DataGuide/) 的数据表语义，并参考 [jcy](https://github.com/jcymeow/jcy) 的完整 Mod 结构。原始重制版资源通过 [casc-modern](https://github.com/TrayHard/casc-modern) 读取；读取的是安装包资源，不是游戏进程内存。

### 独立 Mod 工具与接收端

Mod 生产端是独立仓库中的 `d2r-audio-mod.exe`，D2RHub 是接收端和易用性编排层。生成器不读取 D2RHub 的配置、账号或数据库，也不修改源 Mod；D2RHub 仅通过显式命令行调用随软件打包的生成器、接收逐行 JSON 进度，并在生成后独立复核 v7 清单。账号选择和启动参数更新始终由 D2RHub 完成。

- 无源 Mod 时，从本机 D2R CASC 提取必要表格、世界实体、状态机、环境音与主界面资源，创建最小 Mod。
- 有 jcy 等已解包 Mod 时，先完整复制到新的组合 Mod，再只改加工目标；源目录不写入。
- 若源 Mod 已占用目标物品的实体、状态机或声音，处理器按该目标的当前资源克隆独立实体和状态机，把原声音混入标记文件，并同步复制普通/低配背包 sprite。这样原本共用一个实体的物品也能使用不同声纹，同时保留模型和物品图标。无法安全保留的 Compound、缺失声音或缺失 sprite 会拒绝生成并给出具体冲突，而不是静默输出不可见物品。
- `audio-telemetry-manifest.json` 会记录每个资源的来源、保留方式、置信度与兼容处理；地图与物品身份分别写入 `audio-telemetry-area-catalog.json` 和 `audio-telemetry-item-catalog.json`。

### 掉落：Flippy 重复载波与生命周期去重

- 直接依据当前 Mod 或游戏原始掉落物状态机，为每个所选基础物品代码生成独立实体与专用状态机。
- 标记声音只写入 `Flippy`（`modeId=5`、`stateId=1`）的 `audioId`；静止地面 `Ground`（`modeId=3`、`stateId=2`）保持为空。
- 状态机保留 `Flippy ↔ Ground` 往返，使地面世界实体持续发送纯声纹；软件把同号连续载波合并为一个逻辑掉落。
- 克隆实体只改为引用这份状态机，并在 `items.json` 中仅把目标代码指向对应克隆；同时复制与原资源同名及其数字变体的普通/低配 sprite。不添加通用音频组件，也不修改 `misc.txt:dropsound` 或 `usesound`。
- v7 为地点和掉落使用独立同步码；33 个符文与最多 94 个扩展物品 ID 使用独立低相关 Gold 码。当前内置目录使用其中 50 个扩展 ID。
- 不同代码同步播放仍可分别解码；同代码在完全相同时间爆落时使用同一签名，单一混音只能判断“该物品存在”，不能推断数量。
- 当前内置扩展类别包括宝石与骷髅、三种护身符、珠宝、三把钥匙、三个器官、四种精华和赦免徽章。它们只表示基础代码，不表示品质、词缀或鉴定结果。

### 地点：标记持续 Ambience

- `SoundEnviron` 的 Day/Night Ambience 是区域持续场景音；处理器为所选范围的每个 Area 分别生成带 AreaId 的原始环境音。
- 原始环境音 PCM 从游戏 CASC 资源提取并保留，标记每 5 秒重复一次，避免只在音轨开头出现一次。
- 两个区域使用独立的 `SoundEnv` 克隆，所以即使原本共用环境配置也能发出不同 AreaId。
- 全部区域模式会复制大量环境音，当前实机数据为 137 个 Area，输出通常约 2–3 GB；路线模式可用于快速诊断。
- 主界面使用独立的五幕前端场景、营火、选角循环、前端事件和选项音乐资源，不复用恐怖区域相关的 `options_hd.flac`；识别后立即结束上一场计时且不开始新场次。

## v7 数据包

- 48kHz；63 码片 BPSK 前导，中心频率 18kHz。
- 20 位载荷使用 17/19kHz FSK，包含协议标记、事件类型、10 位 ID 与 CRC-6；协议类型覆盖符文、扩展物品、Area 和主界面。
- 每个数据包发送两份，流式解码器会合并同一逻辑播放中的副本。
- 默认强度 `-30dBFS`，默认阈值 `0.56`。

## 安装与本轮测试

1. 完全退出 D2R。
2. 在“自动化”中开启音频声纹识别，选择“我玩原版”或现有 Mod，然后点击“一键准备并开启”。
3. D2RHub 自动生成全区域与全部支持物品、复核协议清单，并为监控账号配置 `-mod <组合 Mod 名> -txt`；源 Mod 不会被修改。
4. 若游戏已经运行，重启该账号一次。之后 D2RHub 会按实际启动参数定位协议清单，并在参数或 Mod 不兼容时给出非阻断提示。
5. 进入游戏后确认“音频峰值”不是 0。
6. 依次验证：背包/仓库移动、玩家扔地、怪物爆出、多个不同代码同步爆出、普通/恐怖区域切换，以及退出到主界面。
7. 需要连续样本时，点击“开始声纹诊断录音”，结束后点击“停止并保存”。程序生成单声道 WAV 和同名 `events.json`；只录制目标 D2R 进程，不录制麦克风或其他应用。

通过标准是：背包/仓库移动没有掉落事件；主城和主界面的掉落不入库；野外玩家扔地和怪物爆出在数据库中各只记录一次；低于符文编号门槛的有效声纹不入库；多个不同代码同步爆出能分别识别；普通和恐怖区域下地点均切换正确；退出房间进入主界面后上一场立即停止计时。
