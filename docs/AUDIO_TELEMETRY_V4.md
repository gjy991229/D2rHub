# D2RHub 音频遥测 v4

## 目标与边界

v4 只解决两类事实：当前 D2R 进程处于哪个 `Area Id`，以及哪一种符文发生了地面掉落。它不读取或写入游戏内存，不注入 DLL，不使用 OCR，也不依赖文件读取次数。

无法从同一个 HD 地面实体创建事件中区分怪物爆出与玩家从背包丢下，因此两者都会记录；背包和仓库内部移动不会记录。完全同时落地的两枚同号符文在单一混音信号里不可分辨，只能记作一次；不同符文即使同时播放仍可分别解码。

## 为什么不再使用 ETW 文件请求

实机验证表明，D2R 会在首次使用时读取符文与地图探针 FLAC，之后从进程内缓存播放。ETW 能证明资源被加载过，但第二次掉落或后续地图心跳不再产生文件 I/O，因此不能作为事件源。

缓存不影响音频方案：每次逻辑播放最终仍必须进入该 D2R 进程的音频混音输出。D2RHub 使用 Windows 的按进程回环捕获，只解码目标账号对应的 D2R PID。

## Mod 触发设计

设计依据是 [D2R Data Guide](https://locbones.github.io/D2R_DataGuide/) 中的数据表语义，并参考 [jcy](https://github.com/jcymeow/jcy) 的完整 Mod 结构。

### 符文

- 实机验证发现，重制版会在背包/仓库移动路径中复用 `misc.txt:dropsound`，而地面实体创建时并不可靠。因此 v4.1 不再修改 `misc.txt:dropsound`。
- 生成器给 33 个 `data/hd/items/misc/rune/*.json` 的 `entity_root` 添加一次性 `AudioEmitterComponent`，它只随 HD 地面实体创建；怪物爆出和玩家扔地都会触发。
- 生成器给 `r01`–`r33` 分配独立的 `Sounds.txt` 行，关闭 `Defer Inst`、`Stop Inst`、随机音量、随机音高、分组、循环和时长截断。
- 声音设为 2D，避免距离衰减让一次真实掉落在进程混音里消失。
- 如果源 Mod 含 `data/hd/global/sfx/item/rXX.flac`，生成器保留原 PCM 并混入数据包；若无法定位源资源，才生成纯数据包 FLAC。
- `Stream=0` 是有意设置。缓存资源没有问题，因为检测目标是每次播放后的混音，不是磁盘读取。

### 地图

- 生成器遍历源 `levels.txt` 中全部有效 `Area Id`（v4 上限 1023）。
- 每个地图克隆其原 `SoundEnviron`，因此持续环境音、音乐、室内参数等保持不变。
- 只把克隆行的 Day/Night Event 指向该地图的数据包，事件 `Group Weight=100`，并把 Event Delay 设为 50 帧。按照 Data Guide 的随机公式，心跳约每 33–67 帧，即 1.3–2.7 秒播放一次。
- `levels.txt:SoundEnv` 改为该地图自己的克隆行，使共享同一环境配置的相邻地图仍能给出不同 AreaId。

这是当前表驱动 Mod 条件下的必要取舍：随机环境事件槽会被遥测心跳占用，但持续环境、音乐、怪物、技能和 UI 音频不变。与替换持续 Ambience 相比，它对正常游戏听感的影响最小。

## v4 数据包

- 48kHz 生成；手工输入的 32kHz FLAC 会先转换为 48kHz。
- 63 码片 BPSK 前导，中心频率 18kHz。
- 20 位载荷使用 17/19kHz FSK：协议标记、事件类型、10 位 ID 与 CRC-6。
- 每个文件发送两份数据包；流式解码器会合并同一逻辑播放中的两份副本。
- 默认强度 `-30dBFS`，默认前导阈值 `0.56`。CRC 和字段范围校验共同抑制普通游戏高频音导致的误报。
- Rune ID 为 1–33；Area Id 为 1–1023；另保留 frontend 类型供手工资源使用。

## 生成与使用

1. 打开“设置 → 自动化 → 一键生成可用的音频遥测 Mod”。
2. 源目录选择包含 33 个 HD 符文实体的 `jcy.mpq` 或其他完整已解包 `.mpq` Mod。单独的 excel 目录不足以生成可靠地面触发。
3. 输出目录选择 D2R 安装目录下的 `mods`。生成器绝不覆盖已有 `D2RHubAudioTelemetryV41`，源 Mod 也不会被修改。
4. 生成器先复制完整 Mod，再修改 `sounds/levels/soundenviron`、给 33 个 HD 符文实体加入音频发射器，并生成标记资源；`misc.txt` 原样保留，原 Mod 的其他功能与资源也会保留。
5. 账号启动参数使用 `-mod D2RHubAudioTelemetryV41 -txt`。v4.1 使用新 Mod 名，避免误启用已证实触发错误的旧版。
6. 在 D2RHub 中选择目标账号，开启音频识别。状态卡应显示非零音频峰值；进入地图后最迟约 3 秒出现地图心跳。

## 诊断顺序

1. `音频峰值` 一直为 0：目标 PID 不对，或游戏音效通道/输出被静音。
2. 有峰值但心跳为 0：确认账号实际使用 `D2RHubAudioTelemetryV41` 和 `-txt`，并检查 Mod 目录层级。
3. 心跳偶发漏掉：先把标记强度从 `-30` 调到 `-26dBFS` 后重新生成 Mod；再考虑把识别阈值从 `0.56` 小幅降到 `0.52`。
4. 出现误报：提高阈值到 `0.60`；同时保留最近标记和置信度用于复现。
5. 地图显示为 `Area N`：该音频仍已正确解码，但本机的 `rune-audio-area-catalog.json` 不存在；重新用同一 D2RHub 生成一次 Mod 即可恢复名称。
