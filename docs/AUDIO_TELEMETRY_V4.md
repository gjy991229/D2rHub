# D2RHub 音频遥测 v4.3 女伯爵实机版

## 目标与边界

本版本验证两类事实：符文是否执行了世界掉落动画，以及 D2R 当前处于女伯爵路线的哪个 Area。覆盖罗格营地（1）、黑色荒地（6）、遗忘之塔（20）和高塔地牢 1–5 层（21–25）。它不读取或写入游戏内存，不注入 DLL，不使用 OCR，也不依赖文件读取次数。

怪物爆出与玩家从背包丢下都会执行世界掉落动画，因此都应记录；二者无法仅靠这一音频触发区分。背包和仓库内部移动不应记录。完全同时落地的两枚同号符文在单一混音信号里不可分辨，只能记作一次。

## 已排除的错误路径

- ETW 文件请求：实机确认资源只在首次使用时读取，后续播放来自缓存，因此文件 I/O 不能代表每次事件。
- HD 实体级 `AudioEmitterComponent`：实机确认背包/仓库渲染也会创建同一实体，造成移动物品时误报；同时怪物爆落没有可靠触发，因此 v4.2 起已移除全部这类发射器。
- `SoundEnviron` 随机 Event：虽然表定义存在，但实机没有进入该播放路径，因此不再用于地点心跳。

## v4.3 触发设计

设计依据是 [D2R Data Guide](https://locbones.github.io/D2R_DataGuide/) 的数据表语义，并参考 [jcy](https://github.com/jcymeow/jcy) 的完整 Mod 结构。原始重制版资源通过 [casc-modern](https://github.com/TrayHard/casc-modern) 读取；读取的是安装包资源，不是游戏进程内存。

### 符文：只标记真实 Ground 入口

- 直接依据游戏原始掉落物状态机，为 33 个符文各生成一份专用状态机。
- `Flippy`（`modeId=5`、`stateId=1`）不再携带标记。实机证明该模式会随飞落动画约每 0.333 秒重入，即使删除反向转换也会重复发声。
- 标记声音只写入静止地面 `Ground`（`modeId=3`、`stateId=2`）的 `audioId`，并删除状态机内的人工转换，只让游戏自身的物品模式切换触发一次。
- 符文实体只改为引用这份状态机；不再添加通用音频组件，也不修改 `misc.txt:dropsound` 或 `usesound`。
- 不同符文使用 250ms 的编号时隙错峰发送隐藏数据包，解决多个不同符文完全同步爆落时的 FSK 碰撞。可听见的原版播报不延迟。
- 同号符文在完全相同时间爆落时使用同一资源和同一时隙，单一混音仍只能判断“该符文发生了掉落”，不能推断数量。

### 地点：标记持续 Ambience

- `SoundEnviron` 的 Day/Night Ambience 是区域持续场景音；v4.3 为女伯爵路线八个 Area 分别生成带 AreaId 的原始环境音。
- 原始环境音 PCM 从游戏 CASC 资源提取并保留，场景标记只嵌入音轨文件开头；同一音轨自然循环时即使再次解出，也由场景转换门保持幂等。
- 两个区域使用独立的 `SoundEnv` 克隆，所以即使原本共用环境配置也能发出不同 AreaId。
- 全部 137 个 Area 会复制大量重复环境音，正式全地图生成前先用女伯爵连续刷图录音验证长期切图、错峰和误报率。

## v4 数据包

- 48kHz；63 码片 BPSK 前导，中心频率 18kHz。
- 20 位载荷使用 17/19kHz FSK，包含协议标记、事件类型、10 位 ID 与 CRC-6。
- 每个数据包发送两份，流式解码器会合并同一逻辑播放中的副本。
- 默认强度 `-30dBFS`，默认阈值 `0.56`。

## 安装与本轮测试

1. 完全退出 D2R。
2. 确认 `D2RHubAudioCountessV43` 位于 D2R 的 `mods` 目录。
3. 只使用启动参数 `-mod D2RHubAudioCountessV43 -txt`，不要同时启用旧版。
4. 在 D2RHub 选择目标账号并开启音频识别，确认“音频峰值”不是 0。
5. 依次验证：背包/仓库移动符文、玩家扔地、怪物爆出符文，以及女伯爵路线八个地点。
6. 需要连续样本时，点击“开始女伯爵诊断录音”，结束后点击“停止并保存”。程序生成单声道 WAV 和同名 `events.json`；只录制目标 D2R 进程，不录制麦克风或其他应用。

本轮通过标准是：背包移动没有符文事件；玩家扔地和怪物爆出各识别一次且地面不循环；多个不同符文同步爆出时最终全部识别且没有额外错误符文；八个地点均切换正确。
