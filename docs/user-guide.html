      使用手册

      START HERE · CONCEPTS

      先懂这几个概念，再选你的路线

      多开是基础；识别统计与自动跟房是两项独立扩展，可以只用一个，也可以一起用。第一次使用，先让两个账号都能正常进游戏，再准备需要的扩展。

      概念一句话理解在哪里操作
      账号 / 游戏实例账号是保存的登录与启动配置；启动后对应一个游戏进程和窗口。初始化是完成该账号认证，不是加工 Mod。添加账号；账号与实例
      软件模块给 D2RHub 添加操作面板和运行服务，例如“识别与统计”“自动跟房”。添加模块不代表游戏已经具备对应能力。可选功能 → 模块管理
      源 Mod / 加工成品源 Mod 是你原来使用的游戏内容；加工把所需功能放进一个可供游戏加载的 Mod。原版玩家也要生成成品。Mod 管理 → 加工
      声纹识别Mod 在游戏里发出地点、掉落标记；D2RHub 监听一个指定账号的游戏声音，形成记录。加工时选“声纹识别”；识别与统计中选监听账号
      局内房间工具Mod 提供游戏内建房 / 入房表单；D2RHub 按房名规则操作主号和小号。加工时选“局内房间工具”；自动跟房中配置参与账号
      启动方案 / 自动跟房启动方案负责打开一组账号；自动跟房负责让运行中的账号创建或加入同一房间。启动一组账号后仍需进入角色和局内。主界面启动方案；可选功能 → 自动跟房
      扩展生效的顺序：添加软件模块 → 加工所需游戏功能 → 账号选用加工成品 → 重启该账号游戏 → 开启识别或触发跟房。
      一个 Mod 可以同时包含声纹识别和局内房间工具，不需要叠加两个 Mod。只多开无需这两项功能；自动跟房也不依赖识别统计。

      01 · QUICK START

      按目标选一条最短路线

      ① 先用上多开

      配置路径 → 初始化两个账号 → 分别启动 → 保存常用启动方案。

      ② 自动识别与统计

      添加模块 → 选监听账号 → 准备声纹 Mod → 重启游戏 → 开启识别。

      ③ 主号建房、小号跟随

      添加模块 → 所有参与账号选用房间工具 Mod → 选方案与房名 → 局内触发。

      路线一：从零到两个游戏窗口

      1. 安装并选择模式。安装 Windows 版本，阅读首次说明。打算使用识别或跟房就选“正常模式”；只多开也可选“纯净模式”。后续可在“维护与迁移”切换，程序保存后重启。
      2. 配置运行环境。首次向导或“设置中心 → 运行环境”填写对应客户端的游戏目录（含 D2R.exe）和存档目录。国服、国际服分别配置；仅国服战网客户端认证额外需要 Battle.net.exe。路径详解
      3. 添加第一个账号并完成初始化。点击“添加账号”，按昵称、区服、语言和认证向导操作；网页 Token 需登录这个账号并粘贴取得的 Token。完成后在卡片启动，进入角色。
      4. 添加第二个账号。使用另一个游戏账号重复初始化，确认没有误用第一个账号的凭据，再启动第二个。每个卡片对应自己的游戏窗口。
      5. 保存日常启动方式。两个账号都能独立启动后，创建包含这两个账号的命名启动方案，并按需固定到主界面；下次可一键启动这组账号。需要全部可用账号时使用“启动全部”。
      完成标志：两个账号都进入游戏，各自有窗口且卡片能对应到正确账号。做到这里，多开已经可用；接着按需要选择路线二或三。认证失败先在对应账号重新初始化，路径问题先回“运行环境”处理。

      三个功能一起用：准备一次，日常少点几步

      先完成多开 → 添加“识别与统计”和“自动跟房” → 为主号加工同时包含“声纹识别 + 局内房间工具”的 Mod → 同客户端小号可选用同一成品（也可用各自带房间工具的成品）→ 重启相关游戏 → 监听账号选择主号 → 配置跟房。日常只需启动账号组、进入局内、开启识别，再由 D2RHub 触发主号建房和小号跟随。

      02 · CONNECTIONS

      路径与双客户端配置

      “设置中心 → 运行环境”把本机环境分为两套互不混用的安装档案。

      CN PROFILE

      国服

      供国服账号使用。存档目录通常带有 Diablo II Resurrected (CN) 标识。

      GLOBAL PROFILE

      国际服

      亚服、美服和欧服共用同一套国际服游戏与存档路径，通过网页 Token 认证。

      每套档案需要什么

      • 游戏安装目录：包含 D2R.exe，任何认证方式都需要。
      • 存档目录：包含或将包含 Settings.json，任何认证方式都需要。
      • Battle.net.exe：仅国服战网客户端认证需要；全部账号都用网页 Token 时可以留空。

      如果存档目录暂时没有 Settings.json，账号创建、登录和多开仍可用，但画质编辑、账号独立游戏配置和系统配置快照不可用。先用对应客户端正常进入一次游戏，通常会生成该文件。

      辅助路径

      Agent 目录和 %APPDATA%\Battle.net 用于战网运行环境切换；Edge / Chrome 用于网页 Token 的独立浏览器档案。浏览器不是游戏启动的必需项，但使用内置 Token 获取流程时应配置。

      03 · ACCOUNTS

      账号与认证

      添加账号向导顺序为：昵称 → 区服/语言/配音 → 认证模式 → 获取 Token → 粘贴 Token。选择战网认证后，流程会改为客户端登录、采集本地认证快照并清理临时状态。

      战网账号初始化成功后，以账号目录内带客户端版本清单的 runtime/ 快照作为权威认证来源。若该新版快照缺失、损坏或版区不匹配，程序会要求重新初始化，不会静默改用可能过期的顶层旧文件；只有从未迁移、仍标记为已初始化且能由唯一产品键证明版区的纯旧账号，才允许兼容恢复。

      方式网页 Token（推荐）战网客户端认证
      所需路径国服或国际服游戏 + 存档；获取时需 Edge/Chrome国服游戏 + 存档 + 国服 Battle.net.exe
      启动路径使用本机 DPAPI 加密保存的 Token 直启恢复账号的 Battle.net / UnifiedAuth 本地快照后启动
      特点启动快，不依赖战网客户端常驻适合无法使用网页 Token 的账号，流程更长
      失效处理服务端判定失效时，在账号操作中更新 Token界面按 30 天提示有效状态；过期或登录失败时重新初始化
      凭据安全：Token 经 Windows DPAPI 绑定当前 Windows 用户后落盘。它仍属于敏感凭据，不要复制到 Issue、聊天记录或截图中，也不要分享账号目录。

      账号卡片可以做什么

      • 启动账号、只启动 Battle.net（战网认证账号）、更新 Token 或重新初始化。
      • 修改昵称、区服/认证信息、Mod 启动参数与常用参数列表。
      • 设置游戏窗口 X/Y 位置，切换系统配置或账号独立配置。
      • 展开快速设置修改分辨率和帧率；拖动卡片可改变账号顺序，快捷键位置会随顺序对应。

      04 · LAUNCH

      启动方案与进程控制

      • 单账号：点击账号卡片的启动按钮。
      • 启动全部：按当前账号顺序依次处理所有可启动账号。
      • 启动方案：从工具栏展开已保存的账号组合并直接启动；同一账号可以加入多个方案。
      • 常用方案：在“启动方案”菜单中点击方案右侧的星标，可将其固定在“启动方案”和“一键关闭”之间；点击固定按钮即可直接启动，再次点击星标可移除。
      • 编辑启动方案：新建或编辑时填写方案名并勾选账号，再明确保存。取消编辑不会改变原配置；新增账号不会自动加入已有方案。
      • 启动前检查：启动顺序跟随账号卡片当前排序；只要方案内存在未初始化、已删除或需要迁移 Token 的账号，整个方案启动都会被阻止并提示先处理。
      • 取消：启动队列运行时可以取消；程序会尽量收束本轮产生的战网/认证临时状态。
      • 窗口聚焦：使用已绑定快捷键，或在展开悬浮窗双击账号名称。
      “一键关闭”是强制操作：它会结束当前系统内所有 D2R.exe 进程，可能造成未保存的游戏进度丢失。确认所有游戏都可以退出后再执行。

      多开通过 Windows 进程与句柄管理完成，不修改游戏文件、不写入游戏内存，也不注入 DLL；但第三方工具仍可能受到游戏条款、反作弊策略、系统权限或安全软件影响，请自行评估风险。

      05 · SETTINGS CENTER

      设置中心速查

      运行环境国服/国际服游戏、战网、存档、Agent、Roaming 与浏览器路径
      账号与实例昵称、启动方式、Mod、窗口位置、分辨率、帧率与完整游戏设置
      启动策略Agent 延时杀、进程数阈值或不处理；隔离浏览器和每日更新
      窗口快捷键按账号当前位置绑定全局聚焦组合键
      外观与界面界面语言、主题、主窗口透明度和字体
      后台任务查看进度、取消、重试与诊断时间线
      Mod 管理扫描、选择、编辑共享 Mod，并加工功能模块
      模块管理按需添加或卸载桌面悬浮窗、识别与统计、桌宠和自动跟房
      维护与迁移打开日志目录、重新运行首次配置向导与账号迁移

      可选模块

      进入“设置中心 → 可选功能 → 模块管理”添加真正需要的模块。添加后模块才出现在可选功能导航；卸载会立即停止对应运行能力，但保留原设置供再次添加时恢复。“识别与统计”依赖“桌面悬浮窗”：添加识别模块会自动补齐依赖并开启场景统计与 TZ 播报，卸载悬浮窗时也会一并移除识别模块。桌宠和自动跟房可以独立管理。带有进程控制、输入或自动化风险的模块首次启用前会显示独立说明，未确认不会启用。

      账号独立游戏设置

      选中已初始化账号后，可编辑启动、显示、图形、音频、玩法和地图设置。切换账号、离开设置页或关闭设置中心时会保存待提交的修改；保存失败时停留在当前页面。刷新账号列表或切换其他账号的“覆盖游戏配置”开关，不会清空当前账号的编辑草稿。

      未开启“覆盖游戏配置”时跟随当前存档目录的 Settings.json；开启后，该账号保留自己的快照。需要以当前系统设置为基准时，使用“快照系统配置”。此操作会用系统值替换当前游戏设置草稿。

      主题、透明度与字号

      “外观与界面 → 主程序窗口主题”提供深色、浅色、午夜蓝、森林绿、暖砂五套配色。选中后点击“应用外观”；离开页面或关闭设置也会自动应用。午夜蓝和森林绿使用深底色，暖砂使用暖白底色。主界面透明度与字号可单独调整；“桌面悬浮窗 → 信息悬浮窗主题”也可选择这五套主题，并独立保存。

      窗口与快捷键

      首次运行且没有窗口记录时，主面板按屏幕宽度的 59.4%、高度的 65.3% 居中显示，并适配 Windows 缩放。之后优先恢复你调整过的尺寸和位置。关闭按钮将主面板收起到托盘；再次双击程序快捷方式、使用托盘菜单或主面板快捷键，都可唤回原窗口。

      在“窗口快捷键”中点击录制框并按下组合键。主面板使用同一个快捷键：位于前台时收起，否则恢复并聚焦。账号快捷键按账号卡片顺序对应，拖动排序后位置随之变化。小键盘数字显示为 Num0–Num9，与上方数字行独立；如果旧版本已录制成普通数字，请重新录制。小键盘数字建议保持 NumLock 开启。F12 和 Win 组合键不可用。

      录制期间 Hub 暂停自身热键，录制结束或窗口失焦后恢复。系统占用或模块冲突会在保存时提示，失败时保留原绑定。快捷键由 Windows 原生热键服务处理；桌宠的键鼠响应仅在对应功能开启且可见时运行。

      06 · PERFORMANCE OVERLAY

      性能悬浮窗

      悬浮窗常驻桌面上方，可显示运行账号、当前场景、刷图计时和所选掉落。场景统计窗口会把同类物品合并为 #15 海尔 ×2 一类的计数胶囊；刚识别的掉落会在分组列表上方短时弹出，最多同时显示 3 种。分组列表默认显示最近 5 种，点击“展开其余”可查看全部，再次点击即可收起。

      分组右侧的删除按钮只移除该组最近一次掉落。统计悬浮窗支持贴边自动隐藏，也可切换为只显示识别场景、计时器和本次场次的迷你模式；迷你模式与 TZ 窗口一样支持拖动位置、边缘缩放和双击或 Enter 切换，不开启鼠标穿透。关闭场景统计窗口只会隐藏界面；只要“音频声纹自动识别”仍处于开启状态，按进程捕获、计时与落库会继续运行。

      展开与迷你

      • TZ 播报窗可在任意位置双击切换；场景统计窗在正常模式下双击空白区域切换，账号和计时器仍保留原有操作。
      • 窗口获得焦点时按 Enter 也可切换；统计窗进入迷你模式后仍可用 Enter 返回正常模式。
      • 统计窗与 TZ 迷你窗均通过窗口内交互控制：双击或按 Enter 恢复正常模式，拖动空白区域移动窗口，拖拽边缘缩放；不使用全局鼠标钩子。
      • 正常模式记住用户调整的尺寸；统计窗迷你模式可压缩到单行摘要，仍支持移动和缩放。

      贴边吸附与自动隐藏

      1. 把 TZ 悬浮窗或统计悬浮窗拖到屏幕任一边缘并松开。
      2. 窗口会吸附到最近边缘并平滑推入屏幕外，只保留一条约 8px 的触发边。
      3. 把鼠标移到触发边，窗口会平滑抽出；鼠标离开后再次推入隐藏。
      4. 窗口抽出时向屏幕内部拖走，即可取消吸附。

      吸附位置按当前显示器的可用工作区计算，也适用于副屏和任务栏占用区域。系统启用“减少动态效果”时，抽出/隐藏会改为即时完成。

      MOD PROCESSING · PREPARATION

      Mod 加工：把游戏能力准备好，再交给账号使用

      入口是“设置中心 → Mod 管理”。在识别或跟房页面遇到“开始准备”“前往加工”，也会进入对应的准备流程。内置生成器会生成、校验并应用结果，无需另行安装命令行工具。

      先决定怎么加工

      你的情况选择结果
      一直玩原版加工新 Mod → 原版游戏为所选功能生成独立成品，需要新名称。
      已有喜欢的界面 / 掉落提示 Mod加工新 Mod → 已有 Mod → 选择源 Mod以源 Mod 为基础生成新成品，源目录不改动；需要新名称。
      已经有 D2RHub 加工成品，想增加功能选择已加工 Mod → 勾选要增加的模块 → 增补所选模块校验后原位增补所选成品，保留已有功能；不必另起名称。
      成品显示待更新 / 协议不兼容按页面“更新”引导处理按来源重建、校验后同名替换旧成品；不要把不兼容旧成品当作普通源 Mod 反复加工。

      首次加工的明确流程

      1. 选加工目标。选择一个已初始化账号，软件据此确定国服 / 国际服和 Mod 目录；完成后自动更新的是这个账号的启动参数。
      2. 选来源。首次选“加工新 Mod”，再选“原版游戏”或“已有 Mod”。已有 Mod 不在列表时，先在 Mod 管理添加 / 检查对应客户端目录，再重新扫描。
      3. 选功能。识别统计勾选“声纹识别”；自动跟房勾选“局内房间工具”；两项都用就一起勾选。已有功能会继承并锁定。“死亡后自动退出”是独立可选项，不是识别或跟房的前置条件，也不能防止死亡。
      4. 给新成品命名。例如 HubMain；使用英文字母、数字、短横线、下划线，避免重名和 Windows 保留名称，最长 128 字符。
      5. 关闭使用待修改成品的游戏，再执行加工。点击“开始加工并应用”（识别准备入口可能显示“一键准备并应用”），等待生成、校验和应用完成；失败时先看页面原因。
      6. 让账号加载成品。加工目标会自动写入 -mod HubMain -txt -assettestmode 1，其他无关参数保留。其他账号需在账号 Mod 选择处自行选用成品；自动跟房也可在“参与账号 Mod”逐个选择。
      7. 重启有关游戏。已经运行的进程不会随配置切换 Mod。关闭后重新从 D2RHub 启动，再回识别或跟房面板继续。
      共享的是什么？同一客户端下多个账号可以选同一个成品，修改这个 Mod 会影响所有使用者；“加工目标账号”不等于所有账号自动改用它。国服与国际服按各自安装档案准备。一个账号使用包含所需功能的单一成品，不要同时写源 Mod 和成品两套 -mod 参数。

      完成标志：成品功能标签包含所需能力，账号选用的名称正确，并已用新参数重新启动。回到 识别流程 或 跟房流程；加工成功本身不代表监控或跟房任务已启动。

      07 · AUDIO TELEMETRY

      路线二：让游戏自动记录地点、掉落与用时

      需要：正常模式、一个已初始化账号、包含“声纹识别”的加工 Mod。识别一次监听一个目标账号，不会汇总所有多开窗口的声音；可以只开一个账号使用。

      1. 添加模块。打开“设置中心 → 可选功能 → 模块管理”，添加“识别与统计”并阅读模块说明；软件会同时补齐桌面悬浮窗依赖。
      2. 选监听账号。进入“识别与统计”，在“识别目标账号”选择实际刷图的账号；与自动跟房一起用时通常选主号。
      3. 准备 Mod。点击“开始准备”，按加工流程创建或增补声纹功能，完成后确认该账号选用成品，并重启其游戏。
      4. 开启监控。回到“识别与统计”，打开“音频声纹自动识别”（就绪卡可显示“立即开启”）。游戏运行时应显示“正在捕获 · PID …”；保留游戏声音和音效输出。
      5. 进入野外正常刷图。先看地点信号 / 最近识别是否更新，再看场景计时。主城、主界面、尚未识别的地点不会记录掉落；没有物品掉落时掉落数为零是正常的。
      6. 查看记录。切换到另一个野外、回城或返回主界面后，已完成分段会保存。点击“打开掉落统计图表”查看；正在进行的段先看悬浮窗实时计时。历史为空时先检查时间、角色、路线等筛选。
      完成标志：状态显示正在捕获正确游戏进程，地点信号更新，进入野外开始计时，离开后统计页出现已完成记录。掉落识别依赖实际支持的物品信号，不要求每场都有掉落。

      过滤器与统计筛选不是同一件事

      识别过滤器决定今后哪些已识别事件写入数据库，例如仅记录 #20–#33 符文；修改后点击“诊断工具 → 应用并重启识别”，无需重新加工 Mod。被过滤掉、没有保存的事件以后不能靠放宽筛选补回来。统计页筛选只决定怎样展示已保存记录，不改变原始数据。

      信号从哪里来，哪些物品可以识别

      识别 Mod 由内置的 d2r-audio-mod.exe v1.3.3 独立生成，D2RHub 负责调用生成器、复核输出、配置目标账号，并接收和统计 v7 声纹。生成器不读取 D2RHub 的账号、配置或数据库，也不修改源 Mod。“设置中心 → 可选功能 → 识别与统计”选择一个已初始化账号后，捕获器只监听该账号的 D2R 进程及其子进程。

      生成器已在 独立开源仓库 按 MIT 许可公开，可从其 Releases 单独下载。独立运行支持图形界面和命令行；使用 D2RHub 时无需额外安装或手动运行。

      • 首次新建的两种来源：选择“我玩原版”时从本机游戏资源创建识别 Mod；选择“我使用 Mod”时复制并加工所选现有 Mod，保留其功能且不修改源目录。两种方式都需要为输出的新 Mod 输入名称。
      • 兼容处理：每个所选掉落克隆自己的世界实体与 Flippy ↔ Ground 状态机；原动画、模型、VFX、依赖和原声音均保留，背包/仓库 usesound 与表格 dropsound 不改。
      • 覆盖范围：地图可选女伯爵路线或游戏数据中的全部 137 个区域；掉落可选 33 个符文、宝石与骷髅、护身符、珠宝、钥匙、器官、精华与赦免徽章。
      • 协议：v7 使用独立地点同步码与 127 个低相关掉落签名，默认增益 -30dBFS；地点标记混入原始持续环境音，主界面有独立标记用于立即结束上一场计时。
      • 生命周期：世界物品在地面持续发送时，软件用 6 秒缺席门限合并成一次掉落；捡起并在门限后再次落地可成为新事件。完全同步的多个同名物品无法从同一混合信号推断数量。
      • 落库：所选掉落先写入通用原始观测表；离开当前野外或返回主界面时，独立分段和观测归属在同一数据库事务内保存。
      • 运行诊断：状态卡实时显示音频峰值、数据包、符文、扩展物品、地点信号和最近置信度；先看峰值即可区分“没有捕获到声音”和“有声音但没有标记”。
      启动方式：首次创建识别 Mod 时，工具默认生成全区域和全部支持类别；D2RHub 会复核协议清单，在保留其他无关启动参数的前提下，将目标账号的 Mod 参数固定为 -mod <新 Mod 名> -txt -assettestmode 1；回到识别页确认监控已开启。不要同时启用源 Mod；若游戏已经运行，请重启该账号使新参数生效。

      不同代码的掉落同时播放可以分别识别；同一代码在完全相同时间重叠时，只能视为一次事件。护身符、珠宝等只能识别基础代码，无法仅凭声音判断暗金、套装、品质、词缀或鉴定结果。

      ROOM AUTOMATION

      路线三：主号建房，让小号加入同一房间

      需要：正常模式、至少两个已初始化账号；主号和每个小号都必须加载包含“局内房间工具”的成品。它按你在 D2RHub 中配置的房名创建 / 加入，不会自动读取任意手动创建房间的房号；也不会代替登录、选角色或自动刷图。

      1. 添加模块。“设置中心 → 可选功能 → 模块管理”添加“自动跟房”，阅读模块说明后打开该面板。
      2. 选参与账号和 Mod。指定一个“主账号”，勾选“跟随账号”；在“参与账号 Mod”逐个选用带局内房间工具的成品。缺少时点击“前往加工”，完成后返回。主号也需要房间工具。
      3. 选择操作方案。想直接看见操作过程可选“前台键鼠”，使用 16:9 高清键鼠界面并显示局内工具栏；想让窗口后台接收按键则选“后台按键”，先完成下面的聊天第二键位绑定。
      4. 填写房名与快捷键。例如“房名开头”填 hub-、“下一个序号”填 1、“序号位数”选 3，以下次房名预览 hub-001 为准。填写可选密码，并分别录制不冲突的“创建房间快捷键”“跟随账号快捷键”。
      5. 首次先选“手动跟随”。等待有效配置自动保存，启用模块。用所选 Mod 启动 / 重启所有参与账号，选好角色并分别进入局内；参与者使用可互相加入房间的区服与角色模式。
      6. 创建一间房。在“房间操作”点击“主账号创建房间”（或使用创建快捷键并松开按键），等主号实际进入新房，再点击“让跟随账号加入”。小号使用最近由该流程创建的房名和密码，不会各自增加序号。
      7. 改为自动跟随。掌握首次流程后，将“跟随触发”改成“自动跟随”，设置“建房后等待（秒）”与小号进房方式。等待时间应覆盖主号实际载入所需时间；下次仍由你触发主号创建房间，随后软件按延时派发跟随。
      完成标志：在游戏内确认主号与所选小号进入同一个房间。任务完成表示输入流程执行完毕，不能代替游戏服务端的入房结果；如果房间未建立或小号未加入，先看游戏提示和“后台任务”，处理后再触发跟随。

      两种方案怎么选

      方案启动前准备执行时的表现
      前台键鼠16:9 高清键鼠界面、工具栏可见、从局内开始；不需要聊天键绑定。依次切到游戏窗口，短暂接管键鼠；所有可用小号执行完后切回主号。期间让程序完成操作。
      后台按键选择 Pause / F13 作为聊天第二键位，阅读绑定说明，点击“扫描并更新绑定”，然后重启游戏。向窗口发送按键；可同时或按间隔派发。间隔派发不等待前一个小号实际进房。

      在正常模式下添加“自动跟房”模块，阅读模块说明后，选择一个主号和需要跟随的小号。账号需已初始化并正在运行，且使用包含局内房间工具的 Mod。设置房名前缀、密码、下一房序号及创建 / 加入快捷键；每次主号建房会产生新房号，小号使用最近一组房号和密码。

      先准备房间工具

      在 Mod 管理中加工“局内房间工具”，再重启使用该 Mod 的游戏。当前 r26 将大厅原生表单与局内表单分离，并从本机游戏重建两份高清暂停菜单；源 Mod 在这两份菜单上的自定义外观和 Esc 行为不会继承。旧成品按更新引导重建并在校验后同名替换；完成后请重启所有使用该成品的账号。

      每个 Mod 条目的“显示游戏内右上角按钮”可控制工具栏，无需重新加工。关闭使用该 Mod 的游戏后切换，下次启动生效；共享该 Mod 的账号一起变化。隐藏工具栏后，后台方案的暂停菜单键盘入口仍可使用，但前台方案要求工具栏保持显示。

      方案一：后台按键

      选择聊天第二键位 Pause（默认）或 F13，点击“扫描并更新绑定”同步绑定，再重新进入游戏。扫描会处理对应客户端系统存档目录与游戏 mods/ 下已有的键位副本，并保留首次备份；第一聊天键位无需改为回车。主号与小号可在后台接收按键流程。按住时间默认 50ms，可与松开间隔分别调整。

      方案二：前台键鼠接管

      在“建房 / 入房操作方案”选择前台键鼠接管。此方案无需 Pause / F13 绑定，要求游戏使用 16:9 高清键鼠界面、工具栏可见，且操作开始时位于局内。程序依次切换到目标窗口，打开创建 / 加入表单，全选并粘贴房名，按需更新密码，最后回车；主号首次建房会选择地狱难度。

      主号与小号共用一套时序设置。各小号串行接管；间隔模式还会保留设定的最小开始间隔。所有可用小号完成后自动将焦点切回主号，中途失败或取消则不切回；主号已退出或无法获得焦点时仅记录原因，不重复提交小号。

      操作期间短暂接管键鼠并暂停 Hub 热键。完成、失败或取消后会释放按键、恢复鼠标位置；剪贴板没有被其他程序改动时恢复原内容。窗口被遮挡、最小化、失去前台、工具栏隐藏或布局无法识别时会停止操作并报告原因。开始操作前请松开触发快捷键。

      跟随、取消与升级

      可手动触发小号跟随，或设置建房后自动跟随延时；小号可同时派发或按固定间隔派发，前台方案仍串行操作。任务面板支持取消与查看错误。修改 Mod、聊天键或操作方案后，按提示重启游戏或重新初始化；日常切换方案会保留各方案独立设置。

      08 · LOCAL ANALYTICS

      新版统计页与统计口径

      从主界面顶部的统计按钮，或“设置中心 → 可选功能 → 识别与统计 → 打开掉落统计图表”进入。统计按钮旁的“分享战报”可直接生成当前战报并复制为 PNG 图片，随后可粘贴到聊天、文档或图片编辑器。页面读取本地数据库，并通过仅监听本机回环地址的临时 API 完成刷新、重命名和删除。

      底层分段与多选策略组

      不同名称的野外各自开始、结束并保存独立分段；主城和主界面停止计时。统计页内置女伯爵、地穴、安达利尔、墨菲斯托、Chaos、巴尔等常用 Farm 策略组，首次使用时全部默认开启，也可同时勾选或关闭多条路线；每个预设旁都能直接编辑，修改后的预设保存在本机并可恢复系统默认。自定义策略同样支持新建、编辑和删除。每个原始分段最多归入一个策略，重叠路线不会重复计数。策略只对展示、筛选、导出和战报生效，不修改数据库中的原始分段与掉落归属；没有行程标识的旧记录不会被猜测合并。主界面快捷战报与统计 HTML 共用所选策略、预设修改、战报周期、展示字段和异常场次口径；没有保存过偏好时才使用系统默认值。

      统一筛选

      筛选器可折叠；时间范围、角色、场景、掉落状态和具体符文会同时作用于顶部指标、趋势、对比、热力图、符文视图、截图与明细。明细另有搜索、排序和每页 50 条分页。“优化离群场次”默认开启：先过滤短于或等于滑条阈值且没有掉落的场次，阈值默认 1 秒，可在 0–10 秒间调整；同组样本达到 10 场后，才继续处理偏离场均 10 倍以上或低于 0.1 倍的极端耗时。所有处理只影响统计结果，不改数据库。

      效率与趋势

      总场次、总追踪时间、平均/中位/P90/最佳用时、按日趋势、场景效率和角色对比。

      掉落与时段

      掉落总数、每百场掉落、高级符文、命中率、平均间隔、星期×小时热力图。

      33 号符文图谱

      符文层级、1–33 号密度矩阵和排行榜；点击单个符文可直接加入筛选。

      管理与导出

      高级符文截图画廊、单条/整场删除、场景批量改名，以及筛选后的 CSV / JSON 导出。

      关键指标怎么计算

      指标口径
      一场 / 场次原始口径是一条已完成的野外 scene_record；启用策略后，同一行程中连续命中该策略的分段会先合并，并且整个策略组只计一场。不是一次游戏启动，也不是一次掉落。
      平均 / 中位 / P90 / 最佳策略组先把组内各分段的 timer_seconds 相加，得到该场完整耗时；再对筛选后的“场”计算算术平均、50 分位、90 分位和最小值。例如一组 40 秒 + 60 秒会作为一场 100 秒，而不是两场平均 50 秒。
      掉落数筛选后所有记录的 drops 数组元素总和；同场多个符文分别计数。
      每百场掉落掉落数 ÷ 场次 × 100，方便不同场景样本量对比。
      有掉落场 / 命中率至少一条掉落的场数 ÷ 场次；高级符文命中率则只看 #24–#33。
      高级符文间隔按时间排序后，相邻“含高级符文的场”之间跨过的场次数平均值；样本不足时不显示。
      截图数存在 screenshot_path 的掉落条目数量，不等同于高级符文总数。
      删除不可撤销：在统计页删除整场或单个掉落会直接改写本地数据库。重要数据请先备份 %APPDATA%\D2RHub\stateData 或导出 JSON。

      09 · COMPANION

      Bongo Cat

      在“设置中心 → 桌宠”开启桌宠。猫咪会响应键盘和鼠标输入，可显示随机对话及轻量系统状态提示。

      • 拖动猫咪本体可以改变屏幕位置；右键打开皮肤、计数重置和隐藏菜单。
      • 设置中心可调整 0.5×–5.0× 缩放、气泡对话框和已解锁皮肤。
      • “法师猫咪”属于随机彩蛋解锁项；未解锁时不会出现在可选皮肤中。

      10 · DATA & PRIVACY

      数据位置、备份与更新

      D2RHub 使用当前 Windows 用户的 %APPDATA%\D2RHub 保存运行数据；日志保存在程序可执行文件同级目录：

      位置内容
      %APPDATA%\D2RHub\global_config.json全局路径、界面、启动策略、快捷键、声纹与桌宠设置
      %APPDATA%\D2RHub\accounts\账号元数据、DPAPI 加密 Token、带版本清单的 Battle.net / UnifiedAuth 运行快照、账号游戏设置
      %APPDATA%\D2RHub\modules\可选模块的版本化 sidecar 配置、备份与恢复数据
      %APPDATA%\D2RHub\stateData\data.db场次历史与通用掉落声纹观测数据库（旧符文观测会自动迁移）
      logs\程序运行日志；每次启动新建，自动最多保留 16 个

      从旧版便携格式升级时，程序会自动把程序同级 config 搬迁到用户数据目录；迁移失败会继续使用旧目录并在下次启动重试。如果新旧两处都已有配置、账号或统计数据，程序会保留两边而不会静默合并或覆盖，并在日志中报告冲突。

      应用级说明的接受状态按应用版本保存在当前 Windows 用户的本地存储中，升级版本后会重新显示。确认前不会启动全局输入监听、声纹监控、可选能力监督器或 Mod 启动扫描；可选模块说明则按模块单独记录。

      迁移或重装前，退出 D2RHub 并备份整个 %APPDATA%\D2RHub 目录；如果旧 config 仍存在或日志报告迁移冲突，请在核对完成前同时备份它。排障需要时也可一并备份程序同级 logs。不要在程序运行时手工编辑或覆盖数据库和账号快照。

      程序不会在应用内替换正在运行的可执行文件。“每日检查更新”每天首次启动时检查新版本；发现更新后会打开项目 Release / 安装包页面，由你下载 MSI 或 NSIS 安装包完成升级。

      D2RHub 不会主动上传账号配置、Token 或声纹统计。联网范围包括 Battle.net Token 登录页面、GitHub Releases 更新接口和邪恶区域信息接口；统计数据留在本机。

      11 · TROUBLESHOOTING

      疑难解答

      账号无法创建或对应区服不可选

      检查该客户端的游戏目录和存档目录是否成组配置。国服战网认证还需国服 Battle.net.exe；亚 / 美 / 欧服统一检查国际服档案并使用网页 Token。

      战网初始化超时或快照失效

      确认 Battle.net 已实际登录完成、路径对应正确客户端，并避免同时执行另一个战网认证操作。账号卡片显示过期、runtime/ 快照缺失/损坏或启动失败时，执行重新初始化；不要手工复制顶层旧认证文件来绕过快照校验。

      网页 Token 获取页打不开

      在“运行环境”中重新探测或手动选择 Edge / Chrome，关闭同类型浏览器后重试独立浏览器流程。也可以手动取得 Token 后回到向导粘贴。

      画质设置无法读取

      确认存档路径正确且包含 Settings.json。先用对应国服/国际服客户端正常进入游戏一次，再回到设置中心加载。

      窗口默认大小没有变化

      新比例只用于没有有效窗口记录的首次布局，升级会保留旧尺寸。可直接拖动窗口边缘调整，之后会记住你的选择。

      小键盘快捷键没有反应

      保持 NumLock 开启，在“窗口快捷键”中重新录制，确认显示 Num1 等小键盘名称，而非普通 1。若出现占用提示，换用其他组合键；录制期间和自动输入期间 Hub 热键会暂时停用。

      悬浮窗吸附后找不到

      沿最近使用的屏幕边缘缓慢移动鼠标，触发边会让窗口抽出。仍无法找到时，在“桌面悬浮窗”中关闭再开启悬浮窗，或重启应用。

      迷你窗无法变成单行

      继续从底边向上压缩；到 36 逻辑像素附近会切换为单行，并可降至 18。Windows 缩放比例会影响物理像素，不影响逻辑阈值。

      声纹无数据或识别不稳定

      确认账号使用的是独立工具最新输出的组合 Mod、启动参数包含完整的 -mod <名称> -txt -assettestmode 1、游戏音效未静音、目标账号和运行中的 D2R 一致。Mod 实际发出的类别由工具的 --track 决定；D2RHub 设置只过滤接收后要记录的类别。先看“音频峰值”，再看“地点信号”和掉落计数；日志会提示当前 Mod 清单缺失或协议版本不兼容。

      Mod 已加工，功能还是不可用

      按顺序查看：对应软件模块是否已添加且处于正常模式 → 成品标签是否包含所需功能 → 实际账号是否选用了这个成品 → 游戏是否已重启。加工只自动应用到目标账号；小号没有选用或仍是旧进程，是跟房准备未完成的常见原因。

      正在捕获，但没有场次或掉落

      音频峰值一直为零：检查监听账号是否运行、游戏声音是否有输出。峰值变化但地点信号为零：检查成品、协议和启动参数，并重启游戏。地点正常但无掉落：确认处于野外、物品在支持范围且未被识别过滤器排除。实时有计时但历史为空：先离开当前野外完成分段，再放宽统计页时间和角色筛选。

      主号建房成功，小号没跟上

      先查看跟随触发是否仍为“手动跟随”，小号是否勾选、已运行并处于局内。确认各账号的房间工具就绪、区服与角色模式可互相加入。自动跟随过早时增加“建房后等待（秒）”；后台方案检查当前角色聊天第二键位是否已扫描并重启生效；前台方案检查工具栏、16:9 比例、遮挡与最小化状态。查看后台任务的具体失败步骤，主号房间仍有效时可重新触发“让跟随账号加入”。

      想取消跟房或停止识别

      跟房进行中从“后台任务”取消；关闭自动跟房模块可停止后续快捷键和任务运行。停止识别请关闭“音频声纹自动识别”；仅关闭统计悬浮窗不会停止后台记录。设置会保留，之后可继续使用。

      进一步排查

      从“维护 → 打开日志”查看最新日志。提交 Issue 前删除 Token、Windows 用户名、个人路径和含敏感画面的截图；安全问题请通过项目安全政策私下报告。
