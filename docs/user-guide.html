      D2RHub v0.9.121
      使用手册

      依据当前工作区（版本号 v0.9.121）的最新实现维护，包含尚未发布的变更；已安装发行版可能尚无部分入口。覆盖正常 / 纯净模式、双客户端、多账号认证、Mod 加工、自动跟房与分房、识别统计和悬浮窗。

      适用版本 v0.9.121 Windows 11 Audio Telemetry 本地数据

      找到你需要的操作

      设置分为游戏、扩展和应用三个区域。账号、路径与 Mod 放在游戏区域；在“扩展功能”添加功能，再进入对应设置；外观、快捷键、启动策略和维护属于应用区域。

      加工器随 Hub 安装器更新，Mod 成品独立下载；Mod 下载后不会自动改变所有账号的选择，切换后需要重新启动对应游戏。

      本手册跟随当前源码维护。图示为指定日期的演示数据，部分导航位置可能早于本次整理；操作入口以正文和当前界面为准。首次使用优先完成多开，再按需要添加扩展。

      统一桌面版本

      D2RHub 只维护一个桌面发行版：账号管理、多开、画质设置和 Mod 管理属于核心能力；桌面悬浮窗、识别与统计、桌宠和自动跟房作为内置可选模块按需添加。MSI 与 NSIS 使用相同代码和功能，只是安装格式不同。

      窗口快捷键、Mod 管理支持多开核心能力

      START HERE · CONCEPTS

      先懂这几个概念，再选你的路线

      多开是基础；识别统计与自动跟房是两项独立扩展，可以只用一个，也可以一起用。第一次使用，先让两个账号都能正常进游戏，再准备需要的扩展。

      概念一句话理解在哪里操作
      账号 / 游戏实例账号是保存的登录与启动配置；启动后对应一个游戏进程和窗口。初始化是完成该账号认证，不是加工 Mod。添加账号；账号与实例
      Hub 扩展给 D2RHub 添加操作面板和运行服务，例如“识别与统计”“自动跟房”。添加扩展不代表游戏已经具备对应能力。扩展功能
      源 Mod / 加工成品源 Mod 是你原来使用的游戏内容；加工把所需功能放进一个可供游戏加载的 Mod。原版玩家也要生成成品。Mod 管理 → 加工
      声纹识别Mod 在游戏里发出地点、掉落标记；D2RHub 监听一个指定账号的游戏声音，形成记录。加工时选“声纹识别”；识别与统计中选监听账号
      局内房间工具Mod 提供游戏内建房 / 入房表单；D2RHub 按房名规则操作主号和小号。加工时选“局内房间工具”；自动跟房中配置参与账号
      启动方案 / 自动跟房启动方案保存账号组合、跟房角色、识别账号、布局和启动差异；运行参数共用公共设置。启动后仍需进入角色和局内，再触发建房或跟随。主界面启动方案；扩展 → 自动跟房
      扩展生效的顺序：添加Hub 扩展 → 加工所需游戏功能 → 账号选用加工成品 → 重启该账号游戏 → 开启识别或触发跟房。
      一个 Mod 可以同时包含声纹识别和局内房间工具，不需要叠加两个 Mod。只多开无需这两项功能；自动跟房也不依赖识别统计。

      左侧玩家尸体拾取按钮与同名加工

      在 Mod 加工的功能模块中勾选“左侧玩家尸体拾取按钮”，可以独立加工，也可与其他模块组合。加载成品后，在高清键鼠界面左侧玩家头像上逐人点击按钮，切换该玩家拾取自己尸体的权限；专家模式下是否可用由游戏决定。已有 MYMOD 玩家列表时合并到原列表。通过游戏原生控件切换权限，无需图像识别、截图校准或模拟点击，不提供全员反转快捷键。

      选择已有源 Mod 后，可在“输出方式”选择“沿用源名称”。先关闭使用该 Mod 的游戏；加工器先生成并校验，新 Mod 成功后沿用原名称，原目录整体改名为“源名称_backup_唯一编号”。备份内文件保持原样，保留原来的 .mpq 名称；原始未经加工的备份也可继续作为加工来源。批量加工中对应“同名加工并备份”。

      生成或校验失败时不会替换源目录；替换中断会根据恢复记录恢复或保留已校验结果。备份不会自动删除。如需手动回退，先关闭游戏，将新成品移走，再把备份外层文件夹改回原名称。

      01 · QUICK START

      按目标选一条最短路线

      ① 先用上多开

      配置路径 → 初始化两个账号 → 分别启动 → 保存常用启动方案。

      ② 自动识别与统计

      添加扩展 → 选监听账号 → 准备声纹 Mod → 重启游戏 → 开启识别。

      ③ 主号建房、小号跟随

      添加扩展 → 所有参与账号选用房间工具 Mod → 选方案与房名 → 局内触发。

      路线一：从零到两个游戏窗口

      1. 安装并选择模式。安装 Windows 版本，阅读首次说明。打算使用识别或跟房就选“正常模式”；只多开也可选“纯净模式”。后续可在“维护与迁移”切换，程序保存后重启。
      2. 配置运行环境。首次向导或“设置中心 → 运行环境”填写对应客户端的游戏目录（含 D2R.exe）和存档目录。国服、国际服分别配置；仅国服战网客户端认证额外需要 Battle.net.exe。路径详解
      3. 添加第一个账号并完成初始化。点击“添加账号”，按昵称、区服、语言和认证向导操作；网页 Token 需登录这个账号并粘贴取得的 Token。完成后在卡片启动，进入角色。
      4. 添加第二个账号。使用另一个游戏账号重复初始化，确认没有误用第一个账号的凭据，再启动第二个。每个卡片对应自己的游戏窗口。
      5. 保存日常启动方式。两个账号都能独立启动后，创建包含这两个账号的命名启动方案，并按需固定到主界面；下次可一键启动这组账号。需要全部可用账号时使用“启动全部”。
      完成标志：两个账号都进入游戏，各自有窗口且卡片能对应到正确账号。做到这里，多开已经可用；接着按需要选择路线二或三。认证失败先在对应账号重新初始化，路径问题先回“运行环境”处理。

      三个功能一起用：准备一次，日常少点几步

      先完成多开 → 添加“识别与统计”和“自动跟房” → 为主号加工同时包含“声纹识别 + 局内房间工具”的 Mod → 同客户端小号可选用同一成品（也可用各自带房间工具的成品）→ 重启相关游戏 → 监听账号选择主号 → 配置跟房。日常只需启动账号组、进入局内、开启识别，再由 D2RHub 触发主号建房和小号跟随。

      02 · CONNECTIONS

      路径与双客户端配置

      “设置中心 → 运行环境”把本机环境分为两套互不混用的安装档案。

      CN PROFILE

      国服

      供国服账号使用。存档目录通常带有 Diablo II Resurrected (CN) 标识。

      GLOBAL PROFILE

      国际服

      亚服、美服和欧服共用同一套国际服游戏与存档路径，通过网页 Token 认证。

      每套档案需要什么

      • 游戏安装目录：选择名为 Diablo II Resurrected 的现有文件夹，目录内必须有 D2R.exe；不要选上一级目录或 EXE 文件。
      • 存档／配置目录：国服选择 Diablo II Resurrected (CN)，国际服选择 Diablo II Resurrected 文件夹。它用于画质与配置快照；缺少 Settings.json 不阻止账号认证和多开。
      • Battle.net.exe：选择这个名称的现有文件，仅国服战网客户端认证需要；全部账号都用网页 Token 时可以留空。

      如果存档目录暂时没有 Settings.json，账号创建、登录和多开仍可用，但画质编辑、账号独立游戏配置和系统配置快照不可用。先用对应客户端正常进入一次游戏，通常会生成该文件。

      以上名称只限制最后一级文件夹或文件，前缀路径不限。选择路径和保存修改时会检查名称及是否可访问；不使用的客户端档案可以留空。战网认证启动后若实际游戏目录与 Hub 配置不一致，程序会提示并继续管理本次新游戏进程；请核对战网安装位置与 Hub 路径，识别和跟房会按实际运行目录校验 Mod。

      辅助路径

      Agent 目录和 %APPDATA%\Battle.net 用于战网运行环境切换。配置 Edge / Chrome 后，网页 Token 登录会使用隔离浏览器档案；未配置时，向导会通过系统默认浏览器打开登录页，仍可复制链接完成认证。

      03 · ACCOUNTS

      账号与认证

      添加账号向导分为三步：账号信息 → 认证方式 → 连接账号。第一步集中填写本地昵称、游戏区服、界面语言和配音；在认证方式页可返回修改。网页 Token 方式会打开对应区服的登录页，登录后粘贴完整跳转链接，软件自动提取 Token；复制图示可在页面内展开。选择战网认证后，流程会改为客户端登录、采集本地认证快照并清理临时状态。

      战网账号初始化成功后，以账号目录内带客户端版本清单的 runtime/ 快照作为权威认证来源。若该新版快照缺失、损坏或版区不匹配，程序会要求重新初始化，不会静默改用可能过期的顶层旧文件；只有从未迁移、仍标记为已初始化且能由唯一产品键证明版区的纯旧账号，才允许兼容恢复。

      方式网页 Token（推荐）战网客户端认证
      所需路径对应客户端游戏目录；浏览器可用系统默认值，存档目录用于可选游戏设置国服游戏目录 + 国服 Battle.net.exe；存档目录用于可选游戏设置
      启动路径使用本机 DPAPI 加密保存的 Token 直启恢复账号的 Battle.net / UnifiedAuth 本地快照后启动
      特点启动快，不依赖战网客户端常驻适合无法使用网页 Token 的账号，流程更长
      失效处理服务端判定失效时，在账号操作中更新 Token界面按 30 天提示有效状态；过期或登录失败时重新初始化
      凭据安全：Token 经 Windows DPAPI 绑定当前 Windows 用户后落盘。它仍属于敏感凭据，不要复制到 Issue、聊天记录或截图中，也不要分享账号目录。

      账号卡片可以做什么

      • 启动账号、只启动 Battle.net（战网认证账号）、更新 Token 或重新初始化。
      • 修改昵称、区服/认证信息、Mod 启动参数与常用参数列表。
      • 设置游戏窗口 X/Y 位置，切换系统配置或账号独立配置。
      • 展开快速设置修改分辨率和帧率；拖动卡片的非交互区域可改变账号顺序；按钮、输入框、下拉框等控件保持原操作。也可用 Tab 聚焦卡片，按空格、方向键排序，再按空格确认或 Esc 取消。快捷键位置会随顺序对应。

      04 · LAUNCH

      启动方案与进程控制

      • 单账号：点击账号卡片的启动按钮。
      • 启动全部：按当前账号顺序依次处理所有可启动账号。
      • 启动方案：从工具栏选择已保存方案启动；同一账号可以加入多个方案，各方案保存账号选择和启动差异，运行参数共用公共设置。已有游戏运行时不能启动另一套方案。
      • 常用方案：在“启动方案”菜单中点击方案右侧的星标，可将其固定在“启动方案”和“关闭全部”之间；点击固定按钮即可直接启动，再次点击星标可移除。
      • 批量选择：在主操作栏打开“选择账号”，可全选可启动或运行中的账号，也可点击卡片上的复选框单独选择。选中后操作栏显示“启动选中”或“关闭选中”；在“已选”菜单中可补齐全选或切换选择范围，切换会替换原选择。点击旁边的 × 或按 Esc 可取消选择；菜单打开时 Esc 只关闭菜单。未初始化、配置异常或待确认的账号不能加入启动选择，执行前会再次检查状态。
      • 编辑启动方案：新建或编辑时在同一窗口配置账号与启动差异、跟房角色、识别账号、窗口布局，再明确保存；跟房规则、识别过滤、悬浮窗和启动行为在公共设置中修改。取消不会改变原方案或当前运行；只有编辑方案才能保存方案。旧方案需先补全配置并保存。
      • 启动前检查：完整方案按其保存的账号顺序启动；账号、Mod、跟房、识别与布局统一预检。独立启动按账号参数检查，方案启动按成员实际参数检查。缺少声纹识别、敌对自动重开或局内房间工具时，“启动前检查”列出账号和缺少的功能；可“返回调整”，或“跳过并启动”。跳过后不支持的功能不可用，账号与方案的 Mod 配置保持不变。启动失败后可以补启动本次方案内的账号，固定布局位置不会重新分配。
      • 取消：启动队列运行时可以取消；程序会尽量收束本轮产生的战网/认证临时状态。
      • 窗口聚焦：使用已绑定快捷键，或在展开悬浮窗双击账号名称。
      “关闭全部”是强制操作：它会结束当前系统内所有 D2R.exe 进程，包含未由 Hub 启动的游戏。选中运行中账号后，按钮改为“关闭选中”，只关闭这些账号的游戏进程。两种关闭操作都需要确认，并可能造成未保存的游戏进度丢失。确认目标游戏可以退出后再执行。

      完整方案启动前需要关闭当前游戏。方案保存账号组合、角色、布局和启动差异；跟房规则、延迟、识别过滤、悬浮窗及启动行为使用最新公共设置，不会被再次启动方案覆盖。不指定跟房或识别账号时，该方案暂停对应能力，保留公共开关。游戏设置默认在每次启动时读取账号配置，也可在方案中显式开启覆盖。旧完整方案自动迁移，并保留 global_config.before-shared-schemes.json 原始备份；缺少完整配置的旧方案仍需编辑保存。主程序重启后只恢复仍匹配的运行进程，不会自动重放跟房动作。

      多开通过 Windows 进程与句柄管理完成，不修改游戏文件、不写入游戏内存，也不注入 DLL；但第三方工具仍可能受到游戏条款、反作弊策略、系统权限或安全软件影响，请自行评估风险。

      05 · SETTINGS CENTER

      设置中心速查

      运行环境国服/国际服游戏、战网、存档、Agent、Roaming 与浏览器路径
      账号与实例昵称、启动方式、Mod、窗口位置、分辨率、帧率与完整游戏设置
      窗口布局按启动顺序设置窗口坐标与游戏分辨率，支持拖动预览、边缘吸附和多显示器
      启动策略Agent 延时杀、进程数阈值或不处理；多开后保留战网、隔离浏览器、下载源与每日更新
      窗口快捷键主面板呼出／收起、最多三个启动方案热键、按账号当前位置聚焦游戏
      外观与界面界面语言、主题、主窗口透明度和字体
      后台任务查看进度、取消、重试与诊断时间线
      Mod 管理扫描、选择、编辑共享 Mod，并加工功能模块
      扩展功能按需添加或卸载桌面悬浮窗、识别与统计、桌宠和自动跟房
      维护与迁移打开日志目录、重新运行首次配置向导与账号迁移

      “设置中心 → 启动策略 → 多开后保留战网”默认选择“不保留”。可改选一个已初始化的战网模式账号；当它参与本次启动且整批账号均启动成功后，Hub 会在多开流程结束后单独重新打开该账号的战网客户端，不重复启动游戏。取消或启动失败时跳过；账号删除后会自动取消保留。

      可选模块

      进入“设置中心 → 扩展功能”添加真正需要的模块。添加后模块才出现在扩展导航；卸载会立即停止对应运行能力，但保留原设置供再次添加时恢复。“识别与统计”依赖“桌面悬浮窗”：添加识别模块会自动补齐依赖并开启场景统计与 TZ 播报，卸载悬浮窗时也会一并移除识别模块。桌宠和自动跟房可以独立管理。未安装的自动跟房模块不会初始化管理器或创建模块配置；运行中添加后会按需加载。桌宠设置与衣柜界面首次打开时才加载相关代码。带有进程控制、输入或自动化风险的模块首次启用前会显示独立说明，未确认不会启用。

      账号独立游戏设置

      选中已初始化账号后，可编辑启动、显示、图形、音频、玩法和地图设置。切换账号、离开设置页或关闭设置中心时会保存待提交的修改；保存失败时停留在当前页面。刷新账号列表或切换其他账号的“覆盖游戏配置”开关，不会清空当前账号的编辑草稿。

      未开启“覆盖游戏配置”时跟随当前存档目录的 Settings.json；开启后，该账号保留自己的快照。需要以当前系统设置为基准时，使用“快照系统配置”。此操作会用系统值替换当前游戏设置草稿。

      主题、透明度与字号

      “外观与界面 → 主程序窗口主题”提供深色、浅色、午夜蓝、森林绿、暖砂、雾粉六套配色。点击“应用外观”保存并立即生效；离开页面或关闭设置也会保存并应用。主界面背景不透明度支持 10%–100%，可拖动滑块或输入百分比，文字与控件保持清晰；字号有较小、默认、较大三档。通过“悬浮窗设置”可独立调整悬浮窗主题、不透明度、显示和位置。“游戏实例任务栏独立”对之后启动或重新识别的游戏窗口生效。

      窗口与快捷键

      账号快捷配置和“账号与实例 → 启动”中的“存储当前位置”，会按 PID 或唯一窗口昵称找到此账号的游戏窗口，将当前坐标新增为一个账号位置配置。最小化窗口需要先还原。各处分辨率均可选择建议值或输入自定义宽高，最小为 800×600。

      “窗口布局”首页展示开关、已保存布局胶囊和新建入口。点击胶囊进入编辑，点击“新建布局”打开独立草稿；保存后返回列表并显示保存结果，当前选用的胶囊带有应用标记。在编辑页设置 1–32 个窗口后，可拖动预览、拖动八个手柄，或输入 X、Y 和游戏分辨率。分辨率与账号设置中的分辨率含义相同，写入 Settings.json 的 Screen Resolution (Windowed)，不包含标题栏与窗口边框。画布与窗口列表显示对应账号昵称：运行账号按启动顺序排列，未运行账号按主界面顺序预览。画布按显示器的真实位置展示，支持负坐标、重叠和边缘吸附；按住 Shift 拖动可暂时关闭吸附。选中窗口或昵称后，方向键移动 10 像素，Ctrl＋方向键移动 1 像素，Shift＋方向键调整游戏分辨率。坐标对齐窗口可见边缘；画布包含标题栏和可见边框，游戏启动后会自动校准。允许窗口向工作区左侧或上方移出，但至少保留 64 像素可见区域。

      点击“使用预设”展开 1080p、2K 和 4K 双开至八开的单屏预设：首个启动的主窗口居中，其余窗口平铺或错层堆叠，并尽量保持不小于 1280×720。即使连接双屏，预设也只填充主屏上的草稿；需要保存为自定义布局后，才能在主界面选择。可继续将单个窗口拖到副屏，或在“所在显示器”中切换。显示器断开或分辨率变化后，启动与恢复时仅重新适配坐标，保留设置的游戏分辨率，不因任务栏或较小的工作区而裁小。“检测显示器”会显示检测进度与结果。

      主界面“跟房配置”旁的“窗口布局”按钮可以展开快捷面板，以胶囊切换已保存布局或选择“不使用布局”；按钮左侧圆点控制布局开关。按方案启动时使用方案内的布局副本；运行中可切换或调整当前布局，不会回写任何方案。启用统一布局时，位置和分辨率由布局决定，账号 FPS 保留。启动时临时写入窗口模式及分辨率，不改写账号原有位置或画质配置。方案运行按保存的账号顺序对应位置，普通启动按进程启动时间决定；“恢复布局”仅恢复运行中账号的位置和堆叠顺序，不强制改变窗口大小。新的分辨率在下次启动游戏时生效。运行窗口多于布局位置时会提示增加窗口数量。窗口识别优先使用 PID，昵称回退同时核对游戏完整路径，歧义匹配会跳过。

      首次运行或升级后，主面板按屏幕宽度约 70%、高宽比约 0.58 居中显示，并适配工作区和 Windows 缩放。同版本后续启动优先恢复你调整过的尺寸和位置。关闭按钮将主面板收起到托盘；再次双击程序快捷方式、使用托盘菜单或主面板快捷键，都可唤回原窗口。

      在“窗口快捷键”中点击录制框并按下组合键。主面板使用同一个快捷键：位于前台时收起，否则恢复并聚焦。账号快捷键按账号卡片顺序对应，拖动排序后位置随之变化。小键盘数字显示为 Num0–Num9，与上方数字行独立；如果旧版本已录制成普通数字，请重新录制。小键盘数字建议保持 NumLock 开启。F12 和 Win 组合键不可用。

      录制期间 Hub 暂停自身热键，录制结束或窗口失焦后恢复。系统占用或模块冲突会在保存时提示，失败时保留原绑定。快捷键由 Windows 原生热键服务处理；桌宠的键鼠响应仅在对应功能开启且可见时运行。

      在“窗口快捷键 → 启动方案快捷键”先选择已保存的方案，再录制组合键，保存设置后生效。最多绑定三个不同方案；未创建方案时先回主界面创建。组合键不能与主面板、账号聚焦或模块动作冲突。按下后走与主界面相同的启动检查；正在启动、保存设置或重启程序时不会重复派发，也不能绕过已有游戏运行时的方案限制。清除组合键可解除绑定。

      06 · PERFORMANCE OVERLAY

      性能悬浮窗

      悬浮窗常驻桌面上方，可显示运行账号、当前场景、刷图计时和所选掉落。场景统计窗口会把同类物品合并为 #15 海尔 ×2 一类的计数胶囊；刚识别的掉落会在分组列表上方短时弹出，最多同时显示 3 种。分组列表默认显示最近 5 种，点击“展开其余”可查看全部，再次点击即可收起。

      分组右侧的删除按钮只移除该组最近一次掉落。统计悬浮窗支持贴边自动隐藏，也可切换为只显示识别场景、计时器和本次场次的迷你模式；迷你模式与 TZ 窗口一样支持拖动位置、边缘缩放和双击或 Enter 切换，不开启鼠标穿透。关闭场景统计窗口只会隐藏界面；只要“音频声纹自动识别”仍处于开启状态，按进程捕获、计时与落库会继续运行。

      展开与迷你

      • TZ 播报窗可在任意位置双击切换；场景统计窗在正常模式下双击空白区域切换，账号和计时器仍保留原有操作。
      • 窗口获得焦点时按 Enter 也可切换；统计窗进入迷你模式后仍可用 Enter 返回正常模式。
      • 统计窗与 TZ 迷你窗均通过窗口内交互控制：双击或按 Enter 恢复正常模式，拖动空白区域移动窗口，拖拽边缘缩放；不使用全局鼠标钩子。
      • 正常模式记住用户调整的尺寸；统计窗迷你模式可压缩到单行摘要，仍支持移动和缩放。

      贴边吸附与自动隐藏

      1. 把 TZ 悬浮窗或统计悬浮窗拖到屏幕任一边缘并松开。
      2. 窗口会吸附到最近边缘并平滑推入屏幕外，只保留一条约 8px 的触发边。
      3. 把鼠标移到触发边，窗口会平滑抽出；鼠标离开后再次推入隐藏。
      4. 窗口抽出时向屏幕内部拖走，即可取消吸附。

      吸附位置按当前显示器的可用工作区计算，也适用于副屏和任务栏占用区域。系统启用“减少动态效果”时，抽出/隐藏会改为即时完成。

      MOD PROCESSING · PREPARATION

      Mod 加工：把游戏能力准备好，再交给账号使用

      入口是“设置中心 → Mod 管理”。已有成品显示“更新”时，可从卡片直接进入加工页面。Mod 可通过“下载与更新”进入同级下载页，直接下载并自动安装；进度显示在对应资源按钮附近。加工器已随 Hub 内置；缺失或损坏时修复 Hub 安装。下载页按 NullHub、BoHub、LiteHub 排列，以内存参考标签辅助选择；实际占用随场景和设置变化，文件可通过“打开目录”查看。自动更新检查沿用每日检查设置，也可在下载页手动检查。浏览器下载的文件也可通过“导入已下载文件”校验后自动安装。下载会按“设置 → 启动策略 → 下载源”的选择优先使用 Gitee 或 GitHub，失败自动切源。未修改的Mod 可以校验后原位更新并保留备份；已加工或手动修改的 Mod 不会被纯净包覆盖。

      “已安装”显示游戏目录中的 Mod；点击条目“设置”查看详细选项，需要添加能力时使用“加工功能”。“下载与更新”负责获取 Mod 成品。

      从识别或跟房进入加工时，页面会保留目标账号，并提供返回原页面的入口；返回 Mod 库也不会丢失已编辑配方。目标账号已删除或不可用时，需要重新选择，不会自动改用其他账号。“检查更新”会验证受管 Mod 的本地文件，检测到手动修改时先保留现有内容。

      内置加工器与同名重做

      加工器无需单独下载，也不做 Hub 软件版本互认。加工结果按各模块协议和文件结构验证。已有 Mod 增补兼容模块时保留现有内容；覆盖更新或协议不一致时，从原始源 Mod 与旧模块配置重新生成，校验完成后替换同名成品。原始源 Mod 缺失时先恢复来源，失败或取消不会覆盖旧成品。

      “批量加工／更新”提供加工新副本、增补模块、同名重做三种操作。选择同一游戏目录内的多个 Mod，预览目标名称和阻塞原因后串行执行。每项显示成功或失败，可重试失败项，也可在当前项完成后停止。批量完成不会自动切换账号，请在 Mod 库选用。房间工具保留默认地狱和原创建时序；加入确认直接发送原生加入消息。更新后重启使用该 Mod 的游戏。

      先决定怎么加工

      你的情况选择结果
      一直玩原版加工新 Mod → 原版游戏为所选功能生成独立成品，需要新名称。
      已有喜欢的界面 / 掉落提示 Mod加工新 Mod → 已有 Mod → 选择源 Mod可选“生成新副本”并填写新名称；或选“同名加工源 Mod”，校验成功后保留原目录备份并替换。
      已经有 D2RHub 加工成品，想增加功能选择已加工 Mod → 勾选要增加的模块 → 增补所选模块校验后原位增补所选成品，保留已有功能；不必另起名称。
      成品显示待更新 / 协议不兼容按页面“更新”引导处理按来源重建、校验后同名替换旧成品；不要把不兼容旧成品当作普通源 Mod 反复加工。

      首次加工的明确流程

      1. 选加工目标。账号模式选择一个已初始化账号，据此确定国服 / 国际服和 Mod 目录，完成后更新该账号参数。指定游戏进程的无账号模式按安装目录加工，完成后需自行把参数配置到游戏启动器。
      2. 选来源。首次选“加工新 Mod”，再选“原版游戏”或“已有 Mod”。已有 Mod 不在列表时，先在 Mod 管理添加 / 检查对应客户端目录，再重新扫描。
      3. 选功能。按需要勾选“声纹识别”“局内房间工具”等模块。声纹识别下的“场景声纹”默认开启；关闭可减少成品体积，场景改用 OCR，掉落声纹与地区名称目录仍保留。更改已有成品的场景声纹选项会从原始来源重做；改回当前值则无需为此重做。敌对自动重开会同时包含“双击 Esc 下一局”；尸体拾取按钮和场景重开可单独选用。已有功能会继承并锁定。“死亡后自动退出”是独立可选项，不是识别或跟房的前置条件，也不能防止死亡。
      4. 给新成品命名。例如 HubMain；使用英文字母、数字、短横线、下划线，避免重名和 Windows 保留名称，最长 128 字符。
      5. 关闭使用待修改成品的游戏，再执行加工。点击“开始加工并应用”，等待生成、校验和应用完成。加工过程中可以取消，也可以进入后台任务查看进度；取消完成后才能重新执行。失败时页面保留配方。若成品已生成但应用账号失败，重试只应用已有结果，不重复加工。
      6. 加载成品。账号模式会自动写入 -mod HubMain -txt -assettestmode 1，其他无关参数保留。独立启动使用账号参数，启动方案使用方案成员参数；无账号模式请复制生成参数到战网或游戏快捷方式。
      7. 重启有关游戏。已经运行的进程不会随配置切换 Mod。关闭后重新从 D2RHub 启动，再回识别或跟房面板继续。
      共享的是什么？同一客户端下多个账号可以选同一个成品，修改这个 Mod 会影响所有使用者；“加工目标账号”不等于所有账号自动改用它。国服与国际服按各自安装档案准备。一个账号使用包含所需功能的单一成品，不要同时写源 Mod 和成品两套 -mod 参数。

      完成标志：成品功能标签包含所需能力，账号选用的名称正确，并已用新参数重新启动。回到 识别流程 或 跟房流程；加工成功本身不代表监控或跟房任务已启动。

      07 · AUDIO TELEMETRY

      路线二：让游戏自动记录地点、掉落与用时

      需要：正常模式、有效的游戏安装目录和包含“声纹识别”的加工 Mod。可选择一个已初始化账号的昵称，或手动指定外部启动的游戏进程；识别一次监听一个游戏实例。

      无需添加账号：在“监听目标”选择“指定游戏进程（无需账号）”，选择或加工识别 Mod，复制生成的启动参数到战网或游戏快捷方式并重启游戏。在“游戏进程”中根据窗口标题、PID 和 Mod 指定要监听的游戏，即使只运行一个游戏也需明确选择。进程退出或重启后需要重新指定，PID 复用也不会自动接入其他实例。游戏退出后会结算当前野外分段。

      1. 添加扩展。打开“设置中心 → 扩展功能”，添加“识别与统计”并阅读模块说明；软件会同时补齐桌面悬浮窗依赖。
      2. 选监听账号。进入“识别与统计”，在“监听目标”选择实际刷图的账号；与自动跟房一起用时通常选主号。
      3. 准备 Mod。在 Mod 管理中按加工流程创建或增补声纹功能，完成后确认该账号选用成品，并重启其游戏。
      4. 开启监控。回到“识别与统计”，在“记录内容 → 场景计时与掉落截图”启用地区识别并等待资源就绪，再打开“音频声纹自动识别”。游戏运行时应显示“正在捕获 · PID …”；保留游戏声音和音效输出。账号模式在账号或方案成员参数中选用成品；“指定游戏进程”模式保留识别 Mod 选择、准备入口和启动参数复制。
      5. 进入野外正常刷图。确认截图能覆盖进入地区时的红字播报，再看地点识别与场景计时是否更新。已识别的主城和尚未识别的地点不会记录掉落；没有物品掉落时掉落数为零是正常的。
      6. 查看记录。识别到另一个野外、回城播报或结束监控后，已完成分段会保存。点击“打开掉落统计图表”查看；正在进行的段先看悬浮窗实时计时。历史为空时先检查时间、角色、路线等筛选。
      完成标志：状态显示正在捕获正确游戏进程，地点信号更新，进入野外开始计时，离开后统计页出现已完成记录。掉落识别依赖实际支持的物品信号，不要求每场都有掉落。

      视觉地区识别与高号符文截图

      地区声纹和每秒检查一次的截图 OCR 可各自确认场景，结果统一协调；关闭场景声纹的成品依靠 OCR。截图目标沿用监听账号或指定游戏进程。在“识别与统计 → 记录内容 → 场景计时与掉落截图”启用地区识别；首次使用会下载并校验 OCR 模型与推理运行库，在“Mod 管理 → 下载与更新”统一显示为“视觉识别资源包”，可提前下载、校验或打开目录。支持 Gitee 镜像，并遵循下载源设置。用“截图预览”核对区域，比例以游戏客户区为准；最小化、黑帧或截图失败不能作为识别成功。

      恐怖地带（TZ）由地区提示下方文字的 OCR 结果确认，不再只看紫色；识别结果命中“邪恶区域恐怖地带”中的任意一个字，或英文 Terrorized / Terror Zone，即标记当前场景。截图范围须覆盖该提示。标记晚出现时只补充当前场景，不重置计时与掉落；状态保留至下一次场景切换。

      选人或大厅识别暂未提供。直接退出局内不会立即结算，计时会持续到下一次确认场景或结束监控，可能包含菜单停留时间；需要准确结束当前分段时，请先回城并确认识别，或结束监控。

      掉落只由声纹确认，不再使用截图 OCR 核验或拦截。确认 #24–#33 符文后自动保存游戏窗口 PNG，截图失败不影响掉落记录。在“场景计时与掉落截图”中可打开截图目录；图片按日期归档，名称包含掉落时间、场景、符文及记录 ID。数据库仅保存相对路径，图片存放于应用数据目录的 stateData/drop-screenshots。场景 OCR 资源失败可在“诊断与资源”重试；诊断日志默认关闭。

      敌对提示音自动重开

      先给监听 Mod 加工“敌对自动重开”，重启游戏，再在识别页选择监听目标并开启该功能。它共用音频采集目标，可在场景及掉落记录关闭时独立使用。检测到提示音后向目标连续发送四次 Esc，间隔 150 毫秒；所有执行目标都需要加载“双击 Esc 下一局”。敌对自动重开固定在识别页分页上方，默认范围为“监听及已管理窗口”，包括监听窗口及 Hub 管理的游戏窗口；也可切换为“仅监听窗口”。折叠时保留开关与范围下拉框，点击标题展开说明。已有保存的范围选择会保留。

      每次触发后冷却 15 秒，重复提示不会连续派发。结果显示的是按键已发送，仍需确认游戏内状态；提示音本身不能区分是谁向谁宣战。关闭功能或更换监听目标、触发范围，会停止后续按键。监听成品缺少敌对模块时会单独提示不可用；若声纹识别成品有效，场景及掉落记录仍可继续。

      过滤器与统计筛选不是同一件事

      设置页按“监听设置、记录内容、诊断与高级”分区：日常先选监听账号与 Mod；场景计时、掉落截图和过滤在“记录内容”；敌对重开位于分页上方；录音、阈值与故障排查在“诊断与高级”。切换分区保留当前配置。

      识别过滤器决定今后哪些已识别事件写入数据库，例如仅记录 #20–#33 符文；在“识别与统计 → 记录内容”调整后点击“应用掉落过滤”，无需重新加工 Mod。被过滤掉、没有保存的事件以后不能靠放宽筛选补回来。统计页筛选只决定怎样展示已保存记录，不改变原始数据。

      信号从哪里来，哪些物品可以识别

      识别 Mod 由随 Hub 内置的 d2r-audio-mod.exe 独立生成，D2RHub 负责调用生成器、复核输出、配置目标账号，并接收和统计 v7 声纹。生成器不读取 D2RHub 的账号、配置或数据库，也不修改源 Mod。“设置中心 → 扩展 → 识别与统计”可选择已初始化账号的昵称或指定游戏进程；捕获器只监听选定的 D2R 进程及其子进程。指定进程模式不修改账号登录、Mod 或启动配置。

      生成器已在 独立开源仓库 按 MIT 许可公开，可从其 Releases 单独下载。独立运行支持图形界面和命令行；使用 D2RHub 时无需额外安装或手动运行。

      • 首次新建的两种来源：选择“我玩原版”时从本机游戏资源创建识别 Mod；选择“我使用 Mod”时复制并加工所选现有 Mod，保留其功能且不修改源目录。从已有 Mod 加工时，还可选择同名加工；会先保留带 _backup_ 标记的原始目录，校验成功后才替换。
      • 兼容处理：每个所选掉落克隆自己的世界实体与 Flippy ↔ Ground 状态机；原动画、模型、VFX、依赖和原声音均保留，背包/仓库 usesound 与表格 dropsound 不改。
      • 覆盖范围：当前声纹模块生成掉落信号、可选的地区环境声纹，以及供 OCR 匹配的地区目录。地区声纹或 OCR 可确认地点并驱动场景计时；TZ 使用文字 OCR。掉落可选 33 个符文、宝石与骷髅、护身符、珠宝、钥匙、器官、精华与赦免徽章。
      • 协议：继续使用 v7 掉落签名和敌对控制信号；不生成 TZ 或主界面声音。旧成品可能没有地区声纹，可继续使用 OCR；需要更新时从原始未加工来源重做。
      • 生命周期：世界物品在地面持续发送时，软件用缺席门限合并成一次掉落；捡起并在门限后再次落地可成为新事件。完全同步的多个同名物品无法从同一混合信号推断数量。
      • 落库：所选掉落先写入通用原始观测表；识别到地区切换、回城或结束监控时，独立分段和观测归属在同一数据库事务内保存。
      • 运行诊断：状态卡实时显示音频峰值、数据包、符文、扩展物品、地点信号和最近置信度；先看峰值即可区分“没有捕获到声音”和“有声音但没有标记”。
      启动方式：首次创建识别 Mod 时，工具默认生成完整地区目录和全部支持的掉落类别；D2RHub 会复核协议清单，在保留其他无关启动参数的前提下，将目标账号的 Mod 参数固定为 -mod <新 Mod 名> -txt -assettestmode 1；回到识别页确认监控已开启。不要同时启用源 Mod；若游戏已经运行，请重启该账号使新参数生效。

      不同代码的掉落同时播放可以分别识别；同一代码在完全相同时间重叠时，只能视为一次事件。护身符、珠宝等只能识别基础代码，无法仅凭声音判断暗金、套装、品质、词缀或鉴定结果。

      多屏布局与更多游戏设置

      “捕获当前布局”读取当前账号游戏窗口的位置和客户区分辨率，生成可编辑草稿，确认名称后保存。捕获前还原所有目标为普通窗口，并停止拖动；本次启动方案内有账号尚未打开窗口时，需要先全部启动。方案中的位置按账号顺序固定，失败、退出或补启动不会压缩其他账号的位置。

      新保存的布局使用显示器设备接口标识，减少拔插、重连或驱动重新编号导致的双屏对调。旧布局优先按保存的屏幕位置、尺寸迁移；旧布局遇到屏幕排列同时改变时无法可靠还原，请打开布局编辑器核对并重新保存。显示器缺失仍回退主屏。

      游戏设置新增字幕、NPC 问候字幕、单声道、始终奔跑、镜头震动、技能快捷键显示、手柄摇杆交换与独立武器绑定，以及队友、名称、载入开启、居中、房名密码等地图开关。新增项只在该账号实际配置含明确的 0/1 或布尔值时显示，保留原数值/布尔类型。未知设置和枚举暂不开放，保存时保留原值。

      场景重开

      在 Mod 加工中勾选“场景重开”，可单独加工，也可与局内房间工具、双 Esc 或声纹组合。需在 A3、崔凡克或 A4 小站处重开或创房；本模块通过游戏原生小站及房间消息链执行，无需图像识别或 OCR。

      加载加工后的 Mod，使用游戏当前绑定的帮助键触发下一局地狱；与局内房间工具组合时，也可在上述小站处创建房间。模块会替换高清帮助页，原页备份在成品 .mpq 目录的 d2rhub-scene-shortcuts-original-help.json，不修改键位。房名、密码与递增规则仍由自动跟房配置决定。

      ROOM AUTOMATION

      路线三：主号建房，让小号加入同一房间

      需要：正常模式、至少两个已初始化账号；主号和每个小号都必须加载包含“局内房间工具”的成品。它按你在 D2RHub 中配置的房名创建 / 加入，不会自动读取任意手动创建房间的房号；也不会代替登录、选角色或自动刷图。

      1. 添加扩展。“设置中心 → 扩展功能”添加“自动跟房”，阅读模块说明后打开该面板。
      2. 选参与账号和 Mod。指定一个“主账号”，勾选“跟随账号”；启动前会检查本次启动的主号和小号是否加载局内房间工具。遇到提示，可返回调整账号或方案，也可跳过不支持的功能继续启动。
      3. 准备后台跟房。创建快捷键可在任意 D2R 窗口触发，程序自动切到配置主号，所有参与账号处于局内；主号和小号同步预填表单，小号跟随时只提交回车。
      4. 填写房名与快捷键。例如“房名开头”填 hub-、“下一个序号”填 1、“序号位数”选 3，以下次房名预览 hub-001 为准。填写可选密码，并分别录制不冲突的“创建房间快捷键”“跟随账号快捷键”。
      5. 首次先选“手动跟随”。等待有效配置自动保存，启用模块。用所选 Mod 启动 / 重启所有参与账号，选好角色并分别进入局内；参与者使用可互相加入房间的区服与角色模式。
      6. 创建一间房。按配置的“创建房间快捷键”并松开按键，等主号实际进入新房，再按“跟随账号快捷键”。小号使用最近由该流程创建的房名和密码，不会各自增加序号。
      7. 改为自动跟随。掌握首次流程后，将“跟随触发”改成“自动跟随”，设置“建房后等待（秒）”与小号进房方式。等待时间应覆盖主号实际载入所需时间；下次仍由你触发主号创建房间，随后软件按延时派发跟随。
      完成标志：在游戏内确认主号与所选小号进入同一个房间。任务完成表示输入流程执行完毕，不能代替游戏服务端的入房结果；如果房间未建立或小号未加入，先看游戏提示和“后台任务”，处理后再触发跟随。

      导入朋友的规则，只跟房不创建

      自动跟房设置按“房间与操作、参与账号、高级时序”分区。首页配置模式和房间规则；账号选择与顺序集中在“参与账号”；Mod 在账号或方案成员的启动参数中选用。快捷键与进房方式按需展开，高级按键时序留在独立分区。修改仍自动保存。

      主界面“跟房配置”快速设置提供“复制”和“粘贴”。复制内容包含密码；粘贴仅填入房名、密码与序号，不更改账号和快捷键，关闭面板、点击外部、按 Esc 或进入完整设置时自动保存，无需点击应用。无效输入或保存失败时提示并保留当前草稿；进入完整设置会等待保存完成。没有待跟进的建房任务时，直接按跟房快捷键加入当前规则的房间，全部加入指令送达后序号递增；手动或自动跟随配置均可使用。主号仅创建房间时需要。

      1. 创建者在建房前点击房间规则旁的“复制”，把内容发给朋友。内容含密码，请只发给参与者。
      2. 默认模式下手动跟房：粘贴并导入，选择本机跟随账号，直接按跟房快捷键；只需一个本机账号，无需建房主号。使用“拼房跟随”接收聊天信号时，则需配置本机主号，主号与小号一起加入。所有参与账号仍需加载局内房间工具。
      3. 核对双方预览房名、区服和角色模式。默认模式按原版流程创建或跟房；跨电脑协作时，创建方选择“拼房主机”，加入方选择“拼房跟随”。
      4. 全部加入指令送达后，本机下一序号递增。输入失败或取消不递增；间隔模式有指令未送达时也不递增。游戏拒绝入房不能自动识别，需手动核对、调整序号。

      规则只复制前缀、密码、下一序号和补零位数，不导入他人的账号、快捷键或 Mod。它不是跨电脑实时同步：创建者跳房、重试或朋友中途加入时，要重新同步序号。建房后分享时应把跟随者序号设为当前已建房间的序号。

      自动跟房设置和主页“跟房配置”均提供默认、拼房主机、拼房跟随、超级迪亚波罗四个互斥模式，初始选择“默认”。默认不发送或监听聊天；主机在创建前发送；跟随监听本机主号聊天框，主号与小号一起加入，两个房间快捷键均执行加入。仅跟房无需切换前台。设置页自动保存，快捷面板离开时自动保存。模式切换会取消旧流程和待执行信号。拼房跟随不要求开启声纹或地区识别，但需要 OCR 资源就绪、主号聊天窗口可捕获且参与游戏未最小化。诊断日志默认关闭。

      超级迪亚波罗：每个账号创建独立房间

      1. 在“拼房模式”选择“超级迪亚波罗”，选好主号和小号并调整顺序。所有参与账号都须运行、处于局内，并加载局内房间工具。
      2. 设置房名前缀、下一序号、位数和共用密码，等待保存并启用模块。例如前缀 hub-、序号 1、三位数字，配置一主两小。
      3. 在任意 D2R 窗口按“创建房间快捷键”。主号创建 hub-001，小号按配置顺序分别创建 hub-002、hub-003，密码相同；本模式不执行小号跟房，也不接收聊天跟房信号。“跟随账号快捷键”会提示改用创建快捷键。
      4. 在每个游戏窗口核对实际房间。任务会在执行创建前一次预留所有参与账号的序号，上例下一序号变为 4；创建失败或取消后也不会退回已预留的序号。参与账号不可用时先修复该账号，再重新触发。

      聊天信号如何防止重复跟房

      拼房主机在创建前连发三条相同信号，例如 *********** 077 ***********。拼房跟随先宽松检查两侧连续符号的布局，再裁切中间数字送入 OCR；它只用于去重，不会覆盖本机房号。首次有效画面只记录旧消息基线，随后比已消费最大序号更大的信号才会安排跟房。识别成功后等待配置的跟房延迟，不额外固定增加 1 秒；执行期间不继续认领其他消息。

      修改房名前缀、密码、起始序号或位数并成功保存，会重新建立去重会话；粘贴相同规则后保存也能重置。设置页自动保存，快捷面板关闭或离开时自动保存。重置会取消旧等待任务、清空 OCR 缓存，并保留首次画面保护；保存失败时不会重置。普通重启、开关监听和系统自动递增序号会保留记录。

      从小序号重新开始前，先让旧的大序号聊天离开识别区域，避免它重新成为基线。信号在执行前即被持久记录，跟房失败后不会反复重放同一号码；处理游戏提示并核对双方规则后，可手动跟房或重新同步。

      建房与跟随的输入方式

      方案启动前准备执行时的表现
      后台按键参与账号从局内开始，创建时程序自动切到配置主号；直接填写房间表单。向窗口发送按键；可同时或按间隔派发。间隔派发不等待前一个小号实际进房。

      在正常模式下添加“自动跟房”模块，阅读模块说明后，默认模式下选择建房主号和需要跟随的小号；拼房跟随选择聊天监听主号，小号可选，主号也会加入房间。账号需已初始化并正在运行，且使用包含局内房间工具的 Mod。设置房名前缀、密码、下一房序号及创建 / 加入快捷键；每次主号建房会产生新房号，小号使用最近一组房号和密码。

      先准备房间工具

      在 Mod 管理中加工“局内房间工具”，再重启使用该 Mod 的游戏。当前 r33 保留大厅原生表单与局内表单分离，并从本机游戏重建两份高清暂停菜单；源 Mod 在这两份菜单上的自定义外观和 Esc 行为不会继承。旧成品按更新引导重建并在校验后同名替换；完成后请重启所有使用该成品的账号。

      r33 局内房间工具的下一局、创建、加入三个按钮始终隐藏，不再提供显示开关。“双击 Esc 下一局地狱”现为独立可选模块，默认不勾选，可单独加工或与局内房间工具组合。启用后，局内 0.5 秒内双击 Esc 快速进入下一局地狱；单击打开暂停菜单，超时后 Esc 正常返回游戏。后台跟房通过 Esc 和方向键打开表单。旧成品需重新加工并重启游戏。

      r33 创建表单在确认后 10ms 打开暂停菜单，50ms 按顺序发送退出、提交和关闭控制器；加入表单直接发送原生加入消息，不发送退出消息。局内创建默认地狱难度，仍可手动切换。双击 Esc 模块 r4 移除 HUD 中关闭 Esc 接收器的定时器，保留暂停菜单与过渡面板的清理。该时序不是服务器入房确认，任务完成后仍需查看游戏实际状态。

      后台按键与小号提交

      默认模式直接打开并填写房间表单；拼房主机会在填写前打开聊天并发送信号。创建时程序自动切到配置主号，同步预填可用账号，小号跟随阶段只提交一次回车。按住时间默认 50ms，可与松开间隔分别调整。

      “高级输入时序”中的“同步按键超时”控制单条同步按键的最长等待，默认 2000 毫秒（2 秒），可设置为 250–5000 毫秒；仅同步按键方式生效。它与“表单打开后等待”和“小号进房间隔”分别配置。超时后停止流程并尝试释放按键，请查看任务错误与日志，再确认游戏页面后重试。

      跟随、取消与升级

      可手动触发小号跟随，或设置建房后自动跟随延时；小号可同时派发或按固定间隔派发。任务面板支持取消与查看错误。修改 Mod 后请重启游戏。旧前台方案配置自动迁移为后台方案，账号、房号和快捷键等设置保留。

      08 · LOCAL ANALYTICS

      新版统计页与统计口径

      从主界面顶部的统计按钮，或“设置中心 → 扩展 → 识别与统计 → 查看统计图表”进入。统计按钮旁的“分享战报”可直接生成当前战报并复制为 PNG 图片，随后可粘贴到聊天、文档或图片编辑器。页面读取本地数据库，并通过仅监听本机回环地址的临时 API 完成刷新、重命名和删除。

      交互式总览

      统计页默认使用软件的暖砂主题，可切换深色；图片战报保留自己的配色。“时间花在哪里”环图显示有效耗时占比，点击场景图例可筛选，点击“全部场景”恢复。“最近场次耗时”用柱状图展示最近 120 场有效耗时，一柱一场，越高表示用时越长；纵轴标出耗时刻度，横轴按完成时间从较早到最近排列。虚线和文字标明样本中位耗时，柱顶圆点表示有掉落，紫柱表示高级符文。点击柱子或用 Tab 选择可查看角色、时间和掉落数。所有图表沿用当前策略、筛选与异常耗时口径。

      底层分段与多选策略组

      不同名称的野外各自开始、结束并保存独立分段；识别到主城播报后停止计时；当前不识别主界面。统计页内置女伯爵、地穴、安达利尔、墨菲斯托、Chaos、巴尔等常用 Farm 策略组，首次使用时全部默认开启，也可同时勾选或关闭多条路线；每个预设旁都能直接编辑，修改后的预设保存在本机并可恢复系统默认。自定义策略同样支持新建、编辑和删除。每个原始分段最多归入一个策略，重叠路线不会重复计数。策略只对展示、筛选、导出和战报生效，不修改数据库中的原始分段与掉落归属；没有行程标识的旧记录不会被猜测合并。主界面快捷战报与统计 HTML 共用所选策略、预设修改、战报周期、展示字段和异常场次口径；没有保存过偏好时才使用系统默认值。

      统一筛选

      筛选器可折叠；时间范围、角色、场景、掉落状态和具体符文会同时作用于顶部指标、趋势、对比、热力图、符文视图、截图与明细。明细另有搜索、排序和每页 50 条分页。“优化离群场次”默认开启：先过滤短于或等于滑条阈值且没有掉落的场次，阈值默认 1 秒，可在 0–10 秒间调整；同组样本达到 10 场后，才继续处理偏离场均 10 倍以上或低于 0.1 倍的极端耗时。所有处理只影响统计结果，不改数据库。

      效率与趋势

      总场次、总追踪时间、平均/中位/P90/最佳用时、按日趋势、场景效率和角色对比。

      掉落与时段

      掉落总数、每百场掉落、高级符文、命中率、平均间隔、星期×小时热力图。

      33 号符文图谱

      符文层级、1–33 号密度矩阵和排行榜；点击单个符文可直接加入筛选。

      管理与导出

      高级符文截图画廊、单条/整场删除、场景批量改名，以及筛选后的 CSV / JSON 导出。

      关键指标怎么计算

      指标口径
      一场 / 场次原始口径是一条已完成的野外 scene_record；启用策略后，同一行程中连续命中该策略的分段会先合并，并且整个策略组只计一场。不是一次游戏启动，也不是一次掉落。
      平均 / 中位 / P90 / 最佳策略组先把组内各分段的 timer_seconds 相加，得到该场完整耗时；再对筛选后的“场”计算算术平均、50 分位、90 分位和最小值。例如一组 40 秒 + 60 秒会作为一场 100 秒，而不是两场平均 50 秒。
      掉落数筛选后所有记录的 drops 数组元素总和；同场多个符文分别计数。
      每百场掉落掉落数 ÷ 场次 × 100，方便不同场景样本量对比。
      有掉落场 / 命中率至少一条掉落的场数 ÷ 场次；高级符文命中率则只看 #24–#33。
      高级符文间隔按时间排序后，相邻“含高级符文的场”之间跨过的场次数平均值；样本不足时不显示。
      截图数存在 screenshot_path 的掉落条目数量，不等同于高级符文总数。
      删除不可撤销：在统计页删除整场或单个掉落会直接改写本地数据库。重要数据请先备份 %APPDATA%\D2RHub\stateData 或导出 JSON。

      11 · TROUBLESHOOTING

      疑难解答

      账号无法创建或对应区服不可选

      检查对应客户端的游戏目录是否已配置且有效；存档目录不是创建账号的前置条件。国服战网认证还需国服 Battle.net.exe；亚 / 美 / 欧服统一检查国际服游戏目录并使用网页 Token。

      战网初始化超时或快照失效

      确认 Battle.net 已实际登录完成、路径对应正确客户端，并避免同时执行另一个战网认证操作。账号卡片显示过期、runtime/ 快照缺失/损坏或启动失败时，执行重新初始化；不要手工复制顶层旧认证文件来绕过快照校验。

      网页 Token 获取页打不开

      已配置隔离浏览器时，在“运行环境”重新探测或选择 Edge / Chrome，再重试。未配置浏览器时会调用系统默认浏览器，可检查默认浏览器关联；也可手动打开登录页取得完整跳转链接或 Token，再回向导粘贴。

      画质设置无法读取

      确认存档路径正确且包含 Settings.json。先用对应国服/国际服客户端正常进入游戏一次，再回到设置中心加载。

      窗口默认大小没有变化

      首次运行或升级版本后会按默认比例重新居中；同版本后续启动恢复保存的尺寸和位置。可直接拖动窗口边缘调整，等待位置保存后再重启核对。

      小键盘快捷键没有反应

      保持 NumLock 开启，在“窗口快捷键”中重新录制，确认显示 Num1 等小键盘名称，而非普通 1。若出现占用提示，换用其他组合键；录制期间和自动输入期间 Hub 热键会暂时停用。

      悬浮窗吸附后找不到

      沿最近使用的屏幕边缘缓慢移动鼠标，触发边会让窗口抽出。仍无法找到时，在“桌面悬浮窗”中关闭再开启悬浮窗，或重启应用。

      迷你窗无法变成单行

      继续从底边向上压缩；到 36 逻辑像素附近会切换为单行，并可降至 18。Windows 缩放比例会影响物理像素，不影响逻辑阈值。

      声纹无数据或识别不稳定

      确认本次游戏实际加载含声纹的成品，启动参数包含完整的 -mod <名称> -txt -assettestmode 1，游戏音效未静音，监听目标正确。方案成员参数可能与账号默认值不同，应核对本次方案。先看“音频峰值”，再看地点与掉落计数；日志会提示 Mod 清单缺失或协议不兼容。若提示无法确认本次启动的 Mod，请关闭游戏并从 Hub 重新启动，或在监听目标中选择“指定游戏进程”验证连接。

      Mod 已加工，功能还是不可用

      按顺序查看：对应Hub 扩展是否已添加且处于正常模式 → 成品标签是否包含所需功能 → 实际账号是否选用了这个成品 → 游戏是否已重启。加工只自动应用到目标账号；小号没有选用或仍是旧进程，是跟房准备未完成的常见原因。

      正在捕获，但没有场次或掉落

      音频峰值一直为零：检查监听目标是否运行、游戏声音是否有输出。没有场景：检查是否启用了成品的场景声纹，或地区 OCR 已开启、资源就绪且截图覆盖播报；关闭场景声纹时没有地区声音信号属正常。地点正常但无掉落：确认处于野外、物品在支持范围且未被识别过滤器排除。实时有计时但历史为空：先回城、切换野外或结束监控完成分段，再放宽统计页时间和角色筛选。TZ 未标记时核对截图是否覆盖地区提示下方文字，单有紫色不会确认 TZ。

      主号建房成功，小号没跟上

      先检查拼房模式：超级迪亚波罗会分别创建房间，不执行跟随；普通跟房再查看是否仍为“手动跟随”、小号是否勾选、已运行并处于局内。确认本次游戏实际加载局内房间工具，区服与角色模式可互相加入。自动跟随过早时增加“建房后等待（秒）”；创建快捷键可在任意 D2R 窗口触发，程序会自动切到主号。查看后台任务的具体失败步骤，主号房间仍有效时可重新触发跟随。

      想取消跟房或停止识别

      跟房进行中从“后台任务”取消；关闭自动跟房模块可停止后续快捷键和任务运行。停止识别请关闭“音频声纹自动识别”；仅关闭统计悬浮窗不会停止后台记录。设置会保留，之后可继续使用。

      进一步排查

      从“维护 → 打开日志”查看最新日志。提交 Issue 前删除 Token、Windows 用户名、个人路径和含敏感画面的截图；安全问题请通过项目安全政策私下报告。
